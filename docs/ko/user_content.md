# 사용자 콘텐츠 라이브러리(User Content Library)

> 언어: [简体中文](../zh_CN/user_content.md) · [繁體中文](../zh_TW/user_content.md) · [日本語](../ja/user_content.md) · 한국어(본문)

로컬, 오프라인, Mod별 자체 완결. 계정도, 온라인 마켓도, 클라우드 동기화도 없습니다.

## Content Browser v2

캐릭터, 오디오와 이미지를 한 창에서 관리합니다. 이름, 안정 ID, 파일명과 메타데이터를 검색하고 유형별로 필터링할 수 있습니다. 썸네일/기본 스탠딩 이미지, 용도와 현재 프로젝트 참조 수를 표시합니다. ‘미사용’은 현재 프로젝트에서 참조하지 않는다는 뜻이며 자동 삭제하지 않습니다. 메타데이터 보기, 오디오 미리 듣기, 참조 찾기를 제공하고 삭제 전에도 참조를 검사합니다.

## 가져오는 방법

1. 에디터 메뉴 **파일 → 사용자 콘텐츠 라이브러리**.
2. 「오디오 가져오기…」를 클릭하고 로컬 `.ogg` 또는 `.wav`를 선택(개당 20MB 이하).
3. 표시 이름, 네임스페이스, 내부 이름과 용도(음악 / 효과음 / 환경음)를 입력합니다.
4. 안정적인 번호를 얻습니다. 예를 들어 `battle.ogg`를 가져오면:

```text
user:mohui.battle
```

네임스페이스는 기본으로 로컬 사용자 이름의 안전한 형태를 사용하며 변경할 수 있습니다. 같은 번호를 다시 가져오면 거부되어, 몰래 덮어쓰이는 것을 방지합니다.

## 지원하는 형식

| 형식 | 설명 |
| --- | --- |
| `.ogg` | Vorbis. 첫 재생 시 아주 짧은 로딩 지연이 있을 수 있습니다. |
| `.wav` | PCM 8/16비트 또는 32비트 float. 일반적인 WAV는 즉시 재생 가능합니다. |

mp3 / flac / aac는 지원하지 않습니다. 파일 크기 상한 20MB.

## ID란

스토리에 저장되는 것은 참조이며, 파일 경로가 아닙니다.

- 공식 곡 / 효과음: 원래 이름을 그대로 씁니다. 예: `普通_001`, `鈴鐺_001`.
- 사용자 콘텐츠: 반드시 `user:<네임스페이스>.<이름>` 형식이며, 소문자, 숫자, 밑줄만 포함합니다.

표시 이름은 중국어(「决战曲」)도 가능합니다; 내부 ID에는 공백, 중국어, 경로를 포함할 수 없습니다.

## 사용자 콘텐츠는 어디에 저장되나

개발 중에는 로컬에:

```text
%APPDATA%/lom_modkit/repository/audio/<id>/
  content.json
  오디오 파일
```

이것은 에디터 저장소일 뿐입니다. 컴퓨터를 바꾸거나 `.lommod`만 복사하는 플레이어에게는 이 디렉터리가 필요 없습니다.

인물 소개 이미지 / 엔딩 삽화는 여전히 `%APPDATA%/lom_modkit/assets/`에 있으며, 스토리에는 `assets/파일명.png`로 씁니다. 기존 Mod를 깨지 않기 위해 이 시스템과 분리되어 있습니다.

## Story가 저장하는 것

음악 / 효과음 단계의 `name`:

```json
{ "type": "music", "name": "user:mohui.battle" }
```

`C:\Users\...\battle.ogg` 같은 경로의 저장은 금지됩니다.

## 보낸 후에도 로컬 콘텐츠 라이브러리에 의존하나요?

의존하지 않습니다. 보내기는 **현재 스토리가 실제로 참조하는** 사용자 오디오만 `.lommod`에 복사합니다:

```text
assets/user/audio/mohui.battle/content.json
assets/user/audio/mohui.battle/battle.ogg
```

참조되지 않은 가져온 오디오는 패키지에 들어가지 않습니다. 참조 누락, 타입 불일치, 파일 손상 시: 보내기가 바로 실패합니다.

## Mod를 공유하는 방법

보낸 `.lommod`를 다른 사람에게내면 됩니다. 상대가 설치하면 게임 플러그인이 패키지 안에서 재생합니다. 상대 컴퓨터에 당신의 사용자 콘텐츠 라이브러리가 없어도 들을 수 있습니다.

에디터의 「Mod 가져오기」로 다른 사람의 패키지를 열면, 패키지 안의 사용자 오디오가 당신의 로컬 저장소에 등록되어 계속 수정하기 편합니다.

## 리소스 삭제 제한

사용자 콘텐츠 라이브러리에서 삭제할 수 있습니다. 현재 프로젝트의 어떤 음악/효과음 단계가 아직 이 콘텐츠를 사용 중이면 삭제가 차단되고, 어느 챕터의 어느 단계인지 알려줍니다.

## 대사 음성

`say`에 선택 필드 `voice`를 추가할 수 있으며, 값은 반드시 사용자 콘텐츠 참조여야 합니다:

```json
{ "type": "say", "character": "player", "text": "师兄，早。", "voice": "user:mohui.line_01" }
```

`voice`가 없는 대사는 이전과 완전히 같습니다. 있으면 이 문장에 진입할 때 이전 문장의 음성을 정지하고 재생하며, 플레이어가 다음 문장을 누르거나 스토리가 끝/중단될 때 정지합니다. 일반 효과음 노드는 대사 음성을 끊지 않습니다.

음성은 독립된 `audio` 자원이며 캐릭터 `content.json`에 넣지 않습니다. 오디오 metadata에는 선택 필드 `character`를 쓸 수 있습니다. 편집기 관리용 소속이며 재생 규약은 변하지 않습니다:

```json
{
  "schema": 1,
  "content_schema": 1,
  "id": "mohui.line_01",
  "type": "audio",
  "name": "师兄早",
  "audio_kind": "sound",
  "files": { "main": "line_01.wav" },
  "character": "user:mohui.luoxue"
}
```

- 커스텀 캐릭터 상세는 기본 정보 / 스탠딩 / 음성 탭입니다.
- 「음성」 탭에서 가져오면 현재 캐릭터에 자동 연결됩니다. 미리 듣기, 이름 변경, 연결 해제, 삭제도 됩니다.
- 나레이션/시스템 음성은 `character`를 비워 둘 수 있습니다. 이 필드가 없는 기존 오디오도 그대로 동작합니다.
- 공식 인물 id(예: `player`)에도 연결할 수 있으며, 사용자 캐릭터 객체는 만들지 않습니다.
- 대사 단계의 음성 선택기: 인물 대사는 현재 화자에 연결된 음성만 고를 수 있습니다. 나레이션은 연결되지 않은 음성만 고릅니다. 연결되지 않은 인물 음성은 선택할 수 없습니다.
- 삭제는 기존처럼 `say.voice` 참조를 검사합니다.
- 패키징은 스토리가 실제로 참조한 오디오만 모읍니다. 캐릭터에 걸린 미사용 음성은 `.lommod`에 넣지 않습니다.

에디터 대사 단계에서 「대사 음성」을 선택하거나 「가져오기…」를 클릭하세요(화자가 있으면 그 캐릭터에 자동 연결). 「지우기」는 바인딩을 해제합니다.

## 런타임 동작

- 공용 이미지는 `type=image`와 안정된 `user:` 번호를 사용하며 PNG/JPG/JPEG(8MB 이하)를 지원합니다. 배경·CG·Overlay는 같은 콘텐츠 보관함을 공유하고 목록에 썸네일을 표시하며 삭제 전 참조 위치를 검사하고 패키지에는 실제 참조만 포함합니다.

- 공식 이름: 원작 Wwise, 동작은 이전과 완전히 같습니다.
- `user:`: **현재 연출 중인 바로 그 .lommod** 안에서만 찾습니다. 다른 Mod가 같은 이름의 ID를 등록해도 섞이지 않습니다.
- 사용자 지정 오디오는 Windows `waveOut`으로 재생하며, Unity `AudioSource`도 Wwise도 거치지 않습니다. 이 게임의 메인 믹싱은 Wwise라 Unity로 재생하면 종종 소리가 나지 않습니다.
- 볼륨은 대략 게임의 메인 볼륨 × 음악/효과음 슬라이더를 따릅니다; Wwise RTPC가 아니므로 완전히 일치할 수는 없습니다.
- 사용자 지정 fadeout은 출력 볼륨 페이드아웃(이후에도 노드에 따라 대기).
- 사용자 지정 음악으로 전환할 때 먼저 공식 배경 음악을 정지합니다; 공식 `StopMusic`은 원래 환경음도 함께 지웁니다.
- 커스텀 캐릭터는 독립 Runtime(`mod_char_*`)이며 공식 Addressables에 등록하지 않습니다. show / say / hide / move / face / focus / offset / shock / dim / rotate를 지원하고 공식 캐릭터 경로는 바뀌지 않습니다. 체형은 `scale`(50–130, 기본 100)로 발끝을 기준으로 줄이고, 방향은 `art_facing`(기본 왼쪽) 위에 노드 `facing`을 겹칩니다.
- `affinity`는 순수 연출이 아니라 공식 CharacterData 호감도 시스템을 수정하므로 커스텀 캐릭터에서는 계속 지원하지 않습니다. 장기 상태는 Mod 격리 변수를 사용하세요.
- `samples/audio_test/`로 인수 테스트를 할 수 있습니다: 직접 `user:test.bgm` / `user:test.sfx` / `user:test.env`를 가져와 보세요.
## 독립 공유: Content Pack v1

“사용자 콘텐츠 보관함”에서 캐릭터, 오디오 또는 이미지를 골라 오프라인 `.lomcontent`로 내보낼 수 있습니다. 서버에 연결하거나 업로드하지 않습니다. 안정 ID, 유형, SemVer, 작성자, 라이선스, metadata와 각 파일의 크기/SHA-256을 기록합니다.

가져올 때 안전한 경로, 크기, metadata, 파일 및 논리 콘텐츠 해시를 모두 검증한 뒤 원자적으로 설치합니다. audio / character / image는 하나의 ID 공간을 사용합니다. `user:<id>`가 이미 있으면 덮어쓰지 않고 중단합니다. 해시는 작성자 서명이나 공식 인증이 아닙니다.
