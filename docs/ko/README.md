유지보수·워터마크·디컴파일 절차는 중국어 간체만 관리합니다: [`../chs/maintainers.md`](../chs/maintainers.md), [`../chs/decompiled_api.md`](../chs/decompiled_api.md). 게임 본문의 디컴파일 원문은 저장소에 올리지 않습니다.

에디터에서 `Ctrl+Shift+F`를 누르면 프로젝트 전체의 챕터, 노드, 대사, 인물, 소재, 변수, Flag와 이동을 검색하고 결과를 더블 클릭해 바로 이동할 수 있습니다. ‘누가 참조하나요?’로 정확한 참조 위치도 볼 수 있습니다.

‘편집 → 일괄 편집’은 선택한 노드 사이에서 필드 이름과 schema 유형이 정확히 같은 안전한 교집합만 편집하며, 호환되지 않는 필드는 표시하지 않습니다.

‘편집 → 노드 템플릿’에서 하나 또는 연속된 단계를 저장할 수 있습니다. 삽입할 때마다 새 노드 ID를 만들고 템플릿 내부 이동만 다시 연결하며 외부 이동은 유지합니다. 같은 이름의 덮어쓰기와 로컬 절대 리소스 경로는 거부합니다.

‘편집 → 스토리 그룹’은 접을 수 있는 Section / Group 트리 탐색을 제공합니다. 정보는 `_editor.sections`에만 저장되고 노드 순서, 시작점, 이동을 바꾸지 않습니다. 그룹 유무와 관계없이 생성 Lua는 같으며 함수/서브루틴 의미는 없습니다.

‘편집 → 챕터 간 복사 / 붙여넣기’는 대상 ID 충돌을 해결하고 범위 내부 이동을 다시 연결하며 `user:` 참조를 유지합니다. 범위 밖 또는 누락된 참조는 추측해 바꾸지 않고 완료 후 항목별로 경고합니다.

‘편집 → 변수 / Flag 관리자’는 구조화 심볼의 읽기, 쓰기, 첫 쓰기, 확실한 미사용 및 쓰기 전 읽기 가능성을 표시하고 이동/참조 찾기를 제공합니다. 공식 시스템이나 Raw Lua를 폐쇄적으로 판정할 수 없으면 알 수 없음으로 표시합니다.

`F6`는 일상용 Editing 점검이고 `Ctrl+F6`는 출시용 Release 엄격 점검입니다. 둘 다 컴파일, 흐름, 콘텐츠 참조와 데이터 흐름을 검사하며 Release는 출시 metadata와 호환성 규칙을 추가합니다. 미사용 콘텐츠는 자동 삭제하지 않으며 자동 수정은 이야기 의미를 바꾸지 않는 기계적 변경만 수행합니다.

‘도움말 → 진단 번들 내보내기’는 고정 허용 목록 ZIP을 만듭니다. 에디터/Runtime/게임 버전, Manifest, F6 결과, 익명화된 프로젝트 개수, 길이가 제한된 에디터 충돌 로그와 MortalModHost 관련 항목만 고른 Runtime 로그만 포함합니다. 스토리 본문, 사용자 콘텐츠 저장소, Mod, 저장 데이터, 개인 디렉터리, 무관한 로그나 게임 파일은 탐색하거나 복사하지 않습니다. 절대 경로와 사용자 이름은 자리 표시자로 바꿉니다.

‘편집 → 조건 검사기’는 branch를 읽기 쉬운 조건, 심볼 및 실제 분기 대상으로 표시합니다. 모든 CFG 경로가 같은 Mod Flag를 먼저 쓸 때만 항상 참을 증명하고 나머지 Runtime 상태는 알 수 없음으로 둡니다.

‘플레이 테스트 → 스토리 경로 시뮬레이터’는 도달 불가, 끊어진 대상, 출구 없는 순환, 증명된 죽은 분기, 결말 없음 및 챕터 간 이동 오류를 검사합니다. 챕터 간 결말 사슬도 추적하며 Raw Lua와 알 수 없는 Runtime 상태를 확정 결과처럼 보이지 않습니다.

‘플레이 테스트 → 스토리 테스트 러너’는 JSON으로 초기 변수/Flag, choice 동작 및 도달/상태 단언을 선언합니다. 확정 의미는 오프라인 PASS/FAIL로, 주사위·Raw Lua·알 수 없는 게임 상태는 명시적으로 UNSUPPORTED로 처리합니다.
