# AI 代理 CLI / Python API 手冊（story_api）

> 語言：[简体中文](../zh_CN/ai_cli.md) · 繁體中文（本文） · [日本語](../ja/ai_cli.md) · [한국어](../ko/ai_cli.md)

`editor/story_api.py` 是給 AI 代理與腳本呼叫的劇情資料介面：受控寫操作（Python API）
+ argparse 命令列（check / compile / pack / new-story）。本文件面向**以子行程方式
呼叫 CLI 或直接 import 的 AI 代理**，範例均在倉庫真實環境跑通過（Windows + Python
3.10，editor/.venv）。

格式契約（節點類型、包結構、執行階段行為）見 `mod_format.md`，其中 §7 是
story_api 的契約條款；本文件是其操作手冊，二者衝突時以契約為準。

核心規則（契約 §7）：**AI 不直接手寫 story JSON 或 Lua**。一切劇情構建經
story_api——節點由 models 契約預設值產生、欄位按 NODE_SCHEMAS 驗證、未知欄位
一律拒絕，編譯期剩餘問題由 lomc 驗證保底。編輯器與 AI 共用同一套防線。

介面只接受 `models.NODE_SCHEMAS` 目前列出的 46 種節點。不要讓 AI 發明尚不存在的 `combat`、`battle`、`reward`、`quest_*`；目前戰鬥能力僅為 `enemy`、`battle_skill` 與 `goto_scene` 的 `Combat` / `Battle`。

## 1. 環境要求與呼叫方式

- Python 3.10+（倉庫自帶 venv：`editor/.venv`）。story_api 只依賴標準函式庫 +
  `editor/models.py` + `compiler/lomc`，**不依賴 PySide6**，無頭環境可用。
- 依賴倉庫內兩項資源，缺一不可（倉庫自帶，正常複製即有）：
  - `compiler/lomc/`（編譯器；不可用時 check/compile/pack/add_dice 報
    「lomc 编译器不可用」）
  - `data/editor_data.json`（人物/表情/場景/骰子檢查點等官方清單）

### 1.1 原始碼態（開發/AI 子行程）

```bash
cd editor
.venv/Scripts/python story_api.py <子命令> [参数]
```

腳本內部會把 `editor/` 與 `<倉庫根>/compiler` 插入 `sys.path`，**與當前工作目錄
無關**——從倉庫根執行同樣成立：

```bash
editor/.venv/Scripts/python editor/story_api.py check --json samples/demo_mod/story/main.json
# {"ok": true, "errors": [], "warnings": []}
```

路徑推導：`EDITOR_DIR = story_api.py 所在目錄`，`PROJECT_ROOT = 其上一級`，
editor_data 讀 `<倉庫根>/data/editor_data.json`。

### 1.2 凍結態（PyInstaller 打包 exe）

`editor/build_exe.py` 產出 onedir 雙入口包，其中 `story_api_cli.exe` 就是本 CLI，
目標機器無需 Python：

```bash
editor/dist/lom_modkit/story_api_cli.exe check story.json --json
```

與原始碼態的差異僅在路徑推導：`__file__` 指向解包目錄，專案根改為 `_MEIPASS`
（`dist/lom_modkit/_internal`），`data/editor_data.json` 與 lomc 由打包 spec
打進包內。**子命令、參數、輸出格式、退出碼與原始碼態完全一致**。

### 1.3 通用約定

- **退出碼**：`0` 成功；`1` 驗證/編譯/打包/IO 失敗；`2` argparse 用法錯誤
  （缺參數、未知選項，usage 打 stderr）。
- **文字模式**（預設）：結果路徑打 stdout；`警告：...` 與 `錯誤：...` 一律打
  **stderr**。check 全部通過時**無任何輸出**，安靜即成功。
- **--json 模式**：stdout 打**單行**結構化 JSON（UTF-8 直寫位元組流，繞開 Windows
  主控台編碼），stderr 保持乾淨。`--json` 放子命令前或後都生效：

```bash
.venv/Scripts/python story_api.py check --json story.json   # 子命令后
.venv/Scripts/python story_api.py --json check story.json   # 子命令前
```

- 程式入口已把 stdout/stderr reconfigure 為 UTF-8；AI 以子行程呼叫時按 UTF-8
  解碼即可。

## 2. 子命令詳解

範例在 `editor/` 目錄下用 `.venv/Scripts/python story_api.py` 執行；暫存目錄
`C:/Users/mohui666/AppData/Local/Temp/lom_cli_test` 簡寫 `<TMP>`。

### 2.1 check — 驗證 story.json

```
usage: story_api check [-h] [--json] story_json
```

| 參數 | 說明 |
| --- | --- |
| `story_json` | story.json 路徑（位置參數，必填） |
| `--json` | 單行 JSON 輸出 |

行為：讀取並驗證劇情。errors 非空 → 退出碼 1；否則 0。錯誤與警告都是完整中文
句子；錯誤帶 `story.json: ` 來源前綴（該前綴固定為 "story.json"，與實際檔名
無關），警告無前綴。

```bash
# 全部通过：文本模式无任何输出，exit=0
.venv/Scripts/python story_api.py check ../samples/demo_mod/story/main.json
.venv/Scripts/python story_api.py check --json ../samples/demo_mod/story/main.json
# {"ok": true, "errors": [], "warnings": []}

# 有警告（非致命，exit 仍为 0）——transition phase=in 之后没有 out
.venv/Scripts/python story_api.py check --json <TMP>/warn.json
# {"ok": true, "errors": [], "warnings": ["节点 \"n2\"(transition, phase=in) 之后没有 phase=out 解除：TransitionIn 会隐藏剧情 UI 并盖满黑幕……请在其后补一个 phase=out 节点，或改用 scene 节点做转场。"]}

# 有错误（悬空 goto），exit=1
.venv/Scripts/python story_api.py check --json <TMP>/bad.json
# {"ok": false, "errors": ["story.json: 节点 \"n1\": goto 指向不存在的节点 \"not_exist\""], "warnings": []}

# 文件不存在，exit=1
.venv/Scripts/python story_api.py check <TMP>/nope.json
# stderr：错误：story.json 读取失败: [Errno 2] No such file or directory: '...nope.json'
```

> 注意：剛 `new-story` 出來的劇情直接 check 是**不過的**——開場是 show 登場 +
> 空 say，say 是最後一個節點且沒有顯式 goto。這是正常現象，補一個 end 節點即可
> （見 §3.4 工作流程）：
> `{"ok": false, "errors": ["story.json: 节点 \"n2\"(say): 是最后一个节点且没有显式 goto，脚本无法正常结束（请改用 end/goto_scene/raw 节点或显式 goto）"], "warnings": []}`

### 2.2 compile — 編譯 story.json → Lua

```
usage: story_api compile [-h] [-o OUTPUT] [--json] story_json
```

| 參數 | 說明 |
| --- | --- |
| `story_json` | story.json 路徑（位置參數，必填） |
| `-o, --output` | 輸出 .lua 路徑；預設與輸入同目錄、同名 `.lua` |
| `--json` | 單行 JSON 輸出 |

```bash
# 成功：文本模式 stdout 打印产物路径
.venv/Scripts/python story_api.py compile <TMP>/ok.json
# C:\...\lom_cli_test\ok.lua    exit=0

.venv/Scripts/python story_api.py compile <TMP>/ok.json -o <TMP>/out2.lua --json
# {"ok": true, "output": "C:\\...\\out2.lua", "warnings": []}

# 带警告编译（仍成功；Lua 头部同时嵌 `-- lomc 警告：` 注释）
.venv/Scripts/python story_api.py compile <TMP>/warn.json -o <TMP>/warn.lua --json
# {"ok": true, "output": "...\\warn.lua", "warnings": ["节点 \"n2\"(transition, phase=in) 之后没有 phase=out 解除：..."]}

# 失败（不写文件；注意失败时 JSON 只有 ok/errors 两个键，没有 warnings 键）
.venv/Scripts/python story_api.py compile <TMP>/bad.json --json
# {"ok": false, "errors": ["story.json: 节点 \"n1\": goto 指向不存在的节点 \"not_exist\""]}    exit=1
```

產物頭部樣例（`-- Generated by lomc, do not edit` 開頭）：

```lua
-- Generated by lomc, do not edit
-- Source: story/my_tale.json (id=my_tale, title=测试剧情)

-- mod 内剧情 flag 表（不存档，重进游戏清零）
modflags = modflags or {}
mod_set_mood(false)
```

### 2.3 pack — 打包 mod 目錄 → .lommod

```
usage: story_api pack [-h] [-o OUTPUT] [--json] mod_dir
```

| 參數 | 說明 |
| --- | --- |
| `mod_dir` | mod 目錄（含 `manifest.json` 與 `story/` 子目錄，契約 §1/§2） |
| `-o, --output` | 輸出 .lommod 路徑；預設 `<mod目錄>` 同級、同名 `<目錄名>.lommod` |
| `--json` | 單行 JSON 輸出 |

打包前會驗證 manifest、逐個驗證+編譯 story/ 下全部腳本（檔名必須等於內部
id），失敗即整體失敗。產物 zip 內含 `manifest.json`、`story/<id>.json`、
`lua/<id>.lua`、`texts.json`（已讀文字表）。

```bash
.venv/Scripts/python story_api.py pack <TMP>/my_mod -o <TMP>/my_mod_v2.lommod --json
# {"ok": true, "output": "C:/Users/mohui666/AppData/Local/Temp/lom_cli_test/my_mod_v2.lommod"}

# 失败样例
.venv/Scripts/python story_api.py pack <TMP>/no_manifest --json
# {"ok": false, "errors": ["mod 目录缺少 manifest.json: C:\\...\\no_manifest"]}    exit=1
```

> 對 `samples/` 裡的範例 mod 試 pack 時**務必加 `-o` 指到別處**：預設輸出是
> `<mod目錄>.lommod`（如 `samples/demo_mod.lommod`），會覆蓋倉庫已有產物。

### 2.4 new-story — 新建劇情腳本 story.json

| 參數 | 說明 |

| `story_id` | 劇情腳本 id，規則 `[a-zA-Z0-9_-]+`（位置參數，必填） |
| `--title` | 標題，預設「新剧情」 |
| `-o, --output` | 輸出 story.json 路徑（**必填**） |
| `--json` | 單行 JSON 輸出 |


### 2.5 --json 欄位結構彙總

| 子命令 | 成功（exit 0） | 失敗（exit 1） |
| --- | --- | --- |
| check | `{"ok": true, "errors": [], "warnings": [...]}` | `{"ok": false, "errors": [...], "warnings": []}` |
| compile | `{"ok": true, "output": "<lua路径>", "warnings": [...]}` | `{"ok": false, "errors": [...]}`（**無 warnings 鍵**） |
| pack | `{"ok": true, "output": "<lommod路径>"}` | `{"ok": false, "errors": [...]}` |
| new-story | `{"ok": true, "output": "<story.json路径>"}` | `{"ok": false, "errors": [...]}` |

- `ok`：bool，唯一恆在的鍵；`errors`/`warnings`：字串陣列，元素是完整中文
  句子；`output`：字串路徑（Windows 上 JSON 內反斜線跳脫為 `\\`，pack 顯式
  `-o` 時按傳入形式原樣返回）。
- check 是唯一失敗時也帶 `warnings` 鍵的子命令；其餘失敗一律只有 `ok`/`errors`。
- 多條錯誤時 `errors` 按行拆分（lomc 的多行訊息拆成多條）。

## 3. Python API 速查

```python
import sys
sys.path.insert(0, r"<仓库根>/editor")   # 任意 cwd 均可，story_api 内部自理 compiler 路径
import story_api
```

所有函式錯誤訊息全中文；**只拋 `ValueError`**（pack_mod 內部把 lomc.LomcError
轉成 ValueError），驗證/編譯類函式不拋例外、改為返回錯誤列表。

### 3.1 資料與環境

| 函式 | 說明 |
| --- | --- |
| `load_editor_data() -> (dict, bool)` | 讀 `data/editor_data.json`，返回 (資料, 是否保底)。每次都重新讀碟；保底=true 表示檔案缺失/損壞、用了內建保底清單 |

### 3.2 劇情與節點讀寫（寫操作全部走固定規則驗證）

| 函式 | 關鍵約束 |
| --- | --- |
| `new_story(story_id="main", title="新剧情", mood=False) -> dict` | story_id 須匹配 `[a-zA-Z0-9_-]+`；title 須 str；mood 須 bool。返回 show 登場(n1) + 空 say(n2) 開場的劇情 dict（先登場再動作，見 §4 規則 4） |
| `get_node(story, node_id) -> dict` | 不存在 → ValueError。返回的是 story 內的**原物件**（可隨 update 生效） |
| `list_nodes(story) -> list[dict]` | 每項 `{"id", "type", "summary"}`，summary 為中文摘要（如 `对白·唐惟元: 师弟，你来了。`） |
| `add_node(story, node_type, fields=None, after=None) -> dict` | node_type 限 46 種（`models.NODE_TYPES`）；fields 鍵限 NODE_SCHEMAS 合法欄位+通用欄位（id/type/goto），類型按 kind 寬鬆驗證；未知類型/欄位/類型不符 → ValueError。id 自動產生（say1、show2、choice1…），after=節點 id 插到其後、None 追加末尾。**登場防線**：動作類節點的目標人物在前面未登場/已退場時，自動在它前面插一個 show 節點（見 §4 規則 4） |
| `update_node(story, node_id, fields) -> dict` | 同 add_node 的欄位驗證；節點不存在 → ValueError。合併後做 branch 歸一與表情驗證。**登場防線**：更新後若動作人物未登場/已退場，自動在該節點前插入 show，並把指向它的 goto/選項/分支跳轉改指新節點（見 §4 規則 4） |
| `delete_node(story, node_id) -> dict` | 返回被刪節點；**懸空 goto 不攔截**，交給 check_story 報告 |
| `rename_node(story, node_id, new_id) -> dict` | 重新命名節點 id 並同步 start 與全部跳轉引用（goto / choice 選項 / branch cases / dice 去向），返回改名後的節點。新 id 限 `[A-Za-z0-9_-]+`（去首尾空白）；old==new 為空操作；編號被占用或原節點不存在 → ValueError |
| `move_node(story, node_id, delta) -> dict` | delta 只能 ±1；越界（已在開頭/末尾）→ ValueError |
| `set_start(story, node_id) -> dict` | 設定 story["start"]；節點不存在 → ValueError |
| `add_say(story, text, character=None, mode="character", portrait="normal", voice=None, after=None) -> dict` | mode ∈ character/think/narrative/center；character/think 模式 character 必填（人物 id），narrative/center 不寫 character 欄位；text 可換行；(character, portrait) 走官方表情表驗證；voice 可選 user: 音訊引用 |
| `add_scene(story, view, after=None) -> dict` | view 為非空場景 id 字串 |
| `add_choice(story, options, after=None) -> dict` | options 為 [(text, goto), ...] 2~4 項，text 非空 str、goto 為節點 id str；dialog 強制寫 "Options"（見 §4 規則 1） |
| `add_dice(story, check, goto_成功, goto_失敗, goto_大成功="", band_texts=None, after=None) -> dict` | check 必須命中官方元資料（`lomc.dice_data.get_dice_meta`）；2 帶檢查點 goto_成功/goto_失敗 必填、goto_大成功 可空；≥3 帶三個都必填；band_texts 可選逐帶覆寫選項文字，條數=結果帶數、每項非空 |
| `add_death(story, text, death_id, next="Title", title=None, after=None) -> dict` | text 非空（可多行）；death_id 為 ≥900000 的數字字串（約定 9+官方 id）；next 只接受 "Title"；title 可選，預設/空字串不寫欄位（codegen 用「勝敗乃兵家常事」） |

fields 類型驗證約定（`_check_kind`）：int/float 欄位收數值但**拒 bool**
（`True` 傳給 float 欄位會被拒）；bool 欄位只收 bool；options/cases/vars/
dice_options 欄位收 list；其餘一律 str。不修改值，只做驗證。

### 3.3 驗證 / 編譯 / 打包 / 檔案

| 函式 | 返回約定 |
| --- | --- |
| `check_story(story) -> (errors, warnings)` | 兩個字串列表；errors 非空即失敗。errors 帶 `story.json: ` 前綴，warnings 無前綴 |
| `compile_story(story) -> (lua \| None, errors, warnings)` | 失敗 `(None, errors, [])`；成功 `(lua原始碼, [], warnings)`。lua 頭部已嵌 `-- lomc 警告：` 註解 |
| `load_story_json(path) -> dict` | 讀 story.json；讀失敗/結構非法 → ValueError |
| `save_story_json(story, path) -> None` | 寫出 UTF-8、縮排 2、保留中文，末尾帶換行 |
| `pack_mod(mod_dir, output=None) -> str` | 驗證 manifest + 全部編譯 + 打 zip，返回 .lommod 路徑；失敗 → ValueError |

### 3.4 典型工作流程（Python）

新建 → 填起始節點 → 加節點 → check → compile → pack：

```python
import story_api

# 1. 新建（开场是 show 登场 + 空 say；先填 say 文本，默认人物已在 n1 登场）
story = story_api.new_story("my_tale", "测试剧情")
say_id = story["nodes"][1]["id"]
story_api.update_node(story, say_id, {"text": "山门前，风很大。"})

# 2. 加节点（id 自动分配；choice/dice 的 goto 用节点 id 字符串）
story_api.add_scene(story, "center")
story_api.add_say(story, "师弟，你来了。", character="brother4")
#   ↑ brother4 此前未登场：登场防线自动在它前面插一个 show·唐惟元（§4 规则 4）
story_api.add_choice(story, [("迎上去", say_id), ("转身离开", say_id)])
story_api.add_node(story, "end")          # 别忘收尾，否则 check 报「无法正常结束」

# 3. 校验
errors, warnings = story_api.check_story(story)
if errors:
    raise SystemExit("\n".join(errors))

# 4. 编译 + 存档（可选）
lua, errors, warnings = story_api.compile_story(story)
story_api.save_story_json(story, "my_tale.json")

# 5. 打包（mod 目录需含 manifest.json 与 story/<id>.json，文件名=内部 id）
out = story_api.pack_mod("path/to/my_mod")
```

list_nodes 輸出樣例（人物/場景顯示名來自 editor_data 清單，artist1=武師、
brother4=唐惟元、center=校場_白天；n5 是登場防線自動補的 show，插在 n4 前面）：

```python
 {'id': 'n2', 'type': 'say',    'summary': '对白·武师: 山门前，风很大。'},
```

## 4. 寫操作的硬性規則（防寫壞）

這些是把遊戲側已知崩潰坑擋在寫入口的規則，**不要試圖繞過**（繞過也會被
check_story/compile_story 攔下）。各規則的遊戲側機理詳見契約 `mod_format.md`
§3/§4。

1. **choice 外觀鎖死 Options**。`add_choice` 強制 `dialog="Options"`；其它外觀
   是自由場景的 break 格式選單，純文字選項會讓遊戲內選單凍結。即使用
   `update_node` 改成別的外觀，check_story 也會報錯。
2. **dice 檢查點必須命中官方元資料**。`add_dice` 的 check 必須在
   `data/editor_data.json` 的 dice_meta 表裡（可用 `load_editor_data()` 查看，
   測試用例：`S0205_01_001` 為 2 帶、`Ch_6_8_2_Break_01_001` 為 3 帶），
   無元資料的檢查點會讓遊戲內骰子選單崩潰。結果帶數決定 goto 必填項：
   2 帶填 goto_成功/goto_失敗；≥3 帶 goto_大成功 也必填。band_texts 覆寫
   條數必須等於結果帶數。
3. **say 模式與人物連動**。mode=character/think 必須給 character（人物 id）；
   narrative/center 不寫 character 欄位（給了也會被移除）。
4. **動作人物必須先登場（登場防線）**。對不在台上的人物做動作（say 對話/獨白、
   move/face/hide/focus/offset/shock/dim/rotate）會讓遊戲崩掉劇情協程而黑屏。
   `add_node`/`add_say`/`update_node` 寫入時會線性檢查該人物在前面是否已登場
   且未退場，缺失就自動在該節點前面插入一個 `show` 節點（update_node 還會把
   指向它的 goto/選項/分支跳轉改指新 show）。多路徑匯合等複雜情況由編輯器
   「體檢」用圖級分析保底。不要手刪這些自動補的 show。
5. **(character, portrait) 必須在官方角色表情表內**。show/say 節點的角色在表
   且表情不在其列表 → ValueError；角色不在表（自造角色）→ 放行。表情表不可用
   （lomc 缺失）時驗證下沉到 check_story。
6. **未知欄位一律拒絕**。fields 只允許 NODE_SCHEMAS 宣告的欄位 + 通用欄位
   （id/type/goto），多一個鍵就 ValueError 並列出允許集合；類型按 kind 驗證
   （數值欄位拒 bool，bool 欄位拒數值，列表欄位拒字串，反之亦然）。
7. **death_id 必須 ≥900000**（約定 9+官方 id，如官方 10021 → 910021；官方 id
   會觸發官方結局解鎖與記錄，污染存檔）。death 的 next 只允許 "Title"。
8. **branch 鍵欄位歸一**。source=stat 用 stat 欄位並清掉 flag；其餘來源
   （mod/game/flag_value/condition）用 flag 並清掉 stat。add_node/update_node
   自動處理，呼叫方不用管，但不要手寫兩個鍵。
9. **刪除/移動不保證圖完整**。delete_node 產生的懸空 goto、最後一個節點無
   goto 等問題不在寫入口攔截，一律由 check_story 報告——**改完必須 check**。

## 5. 常見錯誤訊息對照表

以下訊息全部為真實執行採集（Python API 拋 ValueError；CLI 文字模式加
`錯誤：`/`警告：` 前綴打 stderr）。

| 錯誤訊息（樣例） | 來源 | 原因與處理 |
| --- | --- | --- |
| `未知节点类型: no_such_type（支持 46 种，见 models.NODE_TYPES）` | add_node | 類型名拼錯；用 `models.NODE_TYPES` 或契約 §3.1 的 46 種 |
| `节点类型 wait 不支持字段: bogus（允许: goto, id, seconds, type）` | add_node/update_node | 欄位名不在類型表；按訊息裡的允許集合改 |
| `节点类型 wait 字段 "seconds" 类型不符（kind=float，应为 数值），实际为 'abc'` | add_node/update_node | 欄位類型錯；注意 `True` 也會被數值欄位拒絕 |
| `通用字段 "goto" 必须是字符串` | add_node/update_node | goto/id/type 只收字串 |
| `after 指定的节点不存在: no_such` | add_* 系列 | after 必須是已有節點 id 或 None |
| `节点不存在: no_such` | get/update/delete/move/rename/set_start | node_id 拼錯或已刪；先 list_nodes 核對 |
| `节点编号已被占用: n5` / `节点编号只使用英文字母、数字、下划线或短横线` | rename_node | 新 id 與現有節點衝突或含非法字元 |
| `delta 只能是 ±1，实际为 2` / `节点 n1 已在开头，无法再移动` | move_node | 只支援逐格移動；越界移動 |
| `choice 选项必须是 2~4 项，实际 1 项` / `第 1 个选项必须是 (text, goto) 二元组` | add_choice | 選項數 2~4；每項是 (text, goto) 二元組 |
| `骰子检查点 "X" 无官方元数据，请在编辑器清单里选择...` | add_dice | check 不在 dice_meta 表；用 `load_editor_data()["dice_meta"]` 選合法檢查點 |
| `检查点 "Ch_6_8_2_Break_01_001" 有 3 个结果带，goto_大成功 必填（最优带）` | add_dice | ≥3 帶檢查點必須給大成功跳轉 |
| `dice band_texts 条数必须等于检查点 "X" 的结果带数（N 条），实际为 M 条` | add_dice | 覆寫文字條數與結果帶數不一致 |
| `mode="character" 时 character 必填（人物 id）` | add_say | character/think 模式必須給人物 id |
| `say 模式非法: 'shout'（允许 character/think/narrative/center）` | add_say | mode 拼錯 |
| `角色 "brother4" 没有表情 "angry3"（该角色表情：angry1、angry2、…、shock）。…KeyNotFoundException…` | add_say/add_node/update_node | 表情 id 不在該角色列表；按訊息列出的合法表情改 |
| `death_id 必须是 ≥900000 的 mod 专属数字 id…实际为 '10021'` | add_death | 用了官方 id；改成 9+官方 id（910021） |
| `death next 非法: 'Free'（原版死亡画面固定返回标题，只允许 Title）` | add_death | next 只接受 Title |
| `剧情脚本 id 非法: '坏id!'（规则 [a-zA-Z0-9_-]+）` | new_story / CLI new-story | id 含非法字元 |
| `story.json: 节点 "n1": goto 指向不存在的节点 "not_exist"` | check/compile | 懸空 goto；把 goto 指向真實節點或刪節點後重連 |
| `story.json: 节点 "n1"(say): 是最后一个节点且没有显式 goto，脚本无法正常结束…` | check/compile | 劇情沒有收尾；末尾補 end/goto_scene/raw 節點或顯式 goto |
| `story.json: 节点 "n2"(choice): dialog 只支持 "Options"。…BreakOptionButton 解析崩溃…` | check/compile | choice 外觀被改成非 Options；改回 Options |
| `story.json: 节点 "n2"(branch): source="stat" 时必填字段 "stat"…` | check/compile | branch stat 來源缺 stat 欄位 |
| `节点 "n2"(transition, phase=in) 之后没有 phase=out 解除…黑幕将一直覆盖到脚本结尾…` | check/compile（**警告**，exit 0） | transition in/out 必須成對；補 out 或改用 scene 轉場 |
| `mod 目录缺少 manifest.json: …` / `mod 目录缺少 story/ 子目录: …` | pack | 按契約 §1/§2 補齊目錄結構 |
| `story/xx.json: 文件名与内部 id 不一致…` | pack | story 檔名必須等於內部 id（my_tale.json ↔ "id": "my_tale"） |
| `story.json 读取失败: [Errno 2] No such file or directory…` | CLI 各子命令 | 路徑錯；注意 Windows 上傳給 exe 的路徑分隔符 |
| `story.json 不是合法 JSON: …` / `story.json 结构非法：缺少 nodes 数组` | load_story_json / CLI | 檔案損壞或不是劇情腳本；不要手寫 JSON，用 API 產生 |
| `lomc 编译器不可用（ImportError: …）。预期位置：…/compiler` | check/compile/pack/add_dice | compiler/ 目錄缺失或被移動；恢復倉庫結構 |
| `usage: story_api ... error: the following arguments are required: -o/--output`（exit=2） | CLI | argparse 用法錯誤；按 usage 補參數 |

## 6. 給 AI 代理的呼叫建議

- **優先 --json**：單行、UTF-8、結構穩定（先讀 `ok`，再按上表取鍵），stderr
  乾淨；文字模式適合人看。
- 每個子行程呼叫都是獨立行程，editor_data 每次重新讀碟——改了
  `data/editor_data.json` 後無需重啟任何東西。
- story dict 在 Python 行程內是可重用物件：多次 add_/update_ 後一次 check；
  但跨行程必須通過 save_story_json / load_story_json 傳遞。
- 寫操作失敗（ValueError）時劇情物件**可能已被部分修改**（如 update_node 先
  合併欄位後做表情驗證），批次構建時建議先小步 check。
- 測試參照：`editor/tests/story_api_test.py`（無 GUI 依賴，可直接
  `.venv/Scripts/python tests/story_api_test.py` 執行）覆蓋全部公開函式。
