# 当前能力与边界

本文对应 **1.6.0**。Rust 编辑器与编译器提供结构化节点，C# `MortalModHost` 接入游戏，包／剧情／内容契约为 **3 / 2 / 1**。版本变化见 [1.6.0 Release](https://github.com/mohui666/lom_modkit/releases/tag/v1.6.0)，本次验证范围见 [测试入口](test_matrix.md)，操作见 [软件使用](software_usage.md)。

MOD 智能自动播放使用游戏的自动按钮，从文字显示完成后按有效字数计算阅读时间；有语音时等待结束并保留 0.3 秒。支持个人速度三档、菜单／日志暂停、手动继续、快进和选项等待；接口及既有证据见 [API 实证](../../research/gameplay_api.md#2026-11-09-mod-智能自动播放)。需要 Host 1.5.3。

## 预览与创作

- 同一窗口可打开多个工程标签，分别保留编辑、撤销、草稿和选择状态；重启恢复已保存工程的标签、当前章节和步骤。未保存内容仍需保存或使用恢复副本。跨标签、跨编辑器窗口可复制粘贴所选步骤，自动分配新编号并保留内部连线；作品素材和其他章节需另行导入。
- 打开作品外层目录时，识别直属工程目录和 `.lommod`；唯一候选直接打开，多个候选供选择。仅选择路径不修改作品内容或存档身份。
- 预览分辨率默认 1920×1080，提供常用宽高比与 160～7680 范围的自定义宽高。选择跨工程保存在个人设置中，重启恢复，不写入作品；视频输出尺寸独立设置。
- 人物按 Sprite 原画布、裁切偏移、站位容器尺寸和原生锚点换算，包含 BC1、BC2、BCB2、Talk 特殊槽；锚点不等于可见脚底。背景相机与人物画布各有适配规则，改变宽高比可能改变裁切和相对位置。作品立绘与表情支持基准图叠加、一键对齐及人工微调。
- Windows 预览可同步播放原版与作品音乐、环境音、普通音效，支持暂停、停止和同时执行组中的延迟、重叠音效。复杂动态混音及原生指令的声音仍需游戏确认。
- Windows「生成视频」使用游戏本体画面与声音，按自动播放节奏输出 MP4，支持当前章、整部作品或当前步骤起播及预设选项。默认在独立桌面的后台游戏进程生成，使用任务专属 Host、演出包和存档目录；不操作正在玩的游戏。画面读回与编码写入采用有上限的并行流水，不通过丢帧缩短耗时。决斗、战役、商店与交互面板等暂不支持自动生成。UI 与 `render-video` CLI 共用流程，见 [视频操作](software_usage.md#页面与游戏配置)。
- 步骤支持多选、批量移动、复制、撤销／重做、全文查找替换、连续对白和同时执行组。每类新步骤的参数默认值可保存为个人偏好，不修改已有步骤。人物移动／位移、旋转、转向、气泡可按字段规则同时执行。
- 对白支持普通人物、旁白、居中旁白和无立绘画外音；字号可显式设置。姓名与称号可独立保持、设置或恢复，跨章并随作品存档保存。压暗可保持、下一句恢复自动或立即恢复自动；本句气泡结束后恢复此前状态。
- 自动保存默认每 5 分钟写回已保存项目，可关闭或调整间隔。手动保存、自动保存和恢复副本均后台写入；保存期间的新编辑仍保留未保存标记。恢复候选与多工程标签重开分别处理，见 [保存与恢复](editor_recovery.md)。
- 回忆、黑白、梦境、火光、模糊变暗支持二维近似预览及渐变。中途 F5 恢复可达路线上的舞台、滤镜和持续背景音；真实 URP 景深、颗粒与任意 Lua 动态状态不保证模拟，二维预览不能替代实机验收。
- 画面调整支持人物、图片和气泡拖动、缩放、吸附、方向键微调及布局复制。气泡按动画时间刷新，屏幕特效可使用本机游戏渲染的缓存帧，支持位置、缩放、翻转、旋转、速度、停止和叠加，见 [特效预览](software_usage.md#特效预览与控制)。
- 原版素材支持中文名和内部 ID 搜索；原版旗标保留实际代号、数值及可核对的用途说明。SDK `asset-query` 返回匹配素材的本机缩略图与可获得的画布、透明边界、锚点、裁切资料；无证据的构图分类或新旧状态标为未知。
- SDK `render-preview`／`render-previews` 可直接输出舞台 PNG；离线检查与 `--smoke-preview` 的模拟状态数不代表渲染帧数或人工看图。报告分别说明实际渲染、素材库状态、缺失能力和游戏验证状态，见 [CLI 参数](cli_parameters.md)。

## 原版剧情与系统

从本机游戏导入原版章节，可修改片段或整章，插入条件剧情和演出。原版调用和赋值转为结构化指令，条件分支保留成立、不成立及汇合去向，局部变量保持作用域。旧整章项目可升级来源结构，新增战斗跨场景续接受局部状态限制。

游戏中按 `Ctrl+F6` 标记章节与对白，编辑器通过「文件 → 原版剧情 → 原版路线图…」或「打开最近游戏标记」定位。静态路线来自本机任务与脚本，动态去向结合当前游戏会话中实际捕获的临时槽和跳转。普通试玩与视频导出均不再叠加可见或隐藏画面水印；作品身份、来源与存档归属检查仍保留。

数值、好感、物品、天赋和奖励等操作可开关系统提示。心上人可按人名选择，结束剧情按自定义章节名选择去向。退出游戏后，编辑器可同步已安装的 Host。

原版章节入口事件支持 `target` 与可选 `from`。CLI `playtest-event` 对这类事件默认从指定原版前置章真实播放，再按原条件、概率和调度进入事件；不强制命中。显式 `boundary` 仅测试入口边界；UI 的临时状态测试仍属边界测试。单章预览不执行原版前置，不能检查其残留界面，见 [事件试玩](events_and_tasks.md#用测试状态验证触发条件)。

## 已实现

- 剧情与演出：对白、人物舞台动作、场景、音乐/音效、背景、CG、Overlay、选项、分支、骰子、结局/死亡卡及多章节跳转。
- 用户内容：离线导入和打包 audio / character / image；自定义角色、逐句语音、BGM、SFX、环境音、背景、CG、Overlay。包收集实际引用内容及填写状态资料的独立人物。
- 战役入口：标题「开始游戏」区分纯原版、原版＋MOD、纯 MOD，后两者使用独立存档页；手动槽、三类自动槽、Universe 最近槽和持久变量均与原版隔离。Manifest 支持地点、时间、Flag、好感触发器。
- 原版系统节点：属性、好感、天赋、物品、官方 Flag、Mission、面板、时间，以及下节所列战斗底层节点。
- 创作与发布：多章节、多选与撤销／重做、项目／节点模板、分区／分组、恢复副本、全文查找替换、离线测试、统计与配音覆盖、Editing／Release 体检、本地发布目录及包检查。Windows 代码保留 F5 试玩请求、MOD 管理、安装检查与 C# Host 回滚；Mac 上禁用游戏接入。
- 作品归属：保留包完整性、源剧情／Lua 归属和存档身份检查；普通试玩与视频不添加可见或隐藏水印。离线检测工具仅用于旧版已带水印媒体，不构成作者身份的数字签名。

完整样例与生成入口见 [Showcase 3.0](../../samples/showcase3/README.md)。

## 当前桌面界面

- Rust／egui 桌面界面，提供工程标签栏、可调栏宽和剧情／素材／游戏／发布页面；标准标题栏显示作品名称与未保存状态。
- 章节支持分组、折叠、改名和移动。新建分组会将当前章节归入该组。步骤小字优先显示节点备注，未填写时显示节点 ID，并保留原有概要。新建／复制章节和素材导入使用独立命名窗口。
- 可选字段直接显示语义明确的默认值，不再用“启用字段”复选框作为入口；内部步骤／章节标识改名放在“编辑 → 高级”。真正的布尔选项仍使用复选框。
- 人物字段直接输入搜索，下方显示可选结果；选择后才写入底层 ID，取消搜索保留原值。同名不同 ID 的数字在搜索前后稳定。作品内容库按有边框的独立行显示名称、右侧类型和选中状态。
- 默认表情、无语音、默认对话模式分别清除对应可选字段；默认对话仍显示人物姓名，用户人物使用其内容名称。流程图按分支、汇合和回路布局，支持缩放、适应宽度、节点点击及选中定位；可识别节点的编译错误链接会定位到该步骤。
- 简体中文、繁體中文、日本語、한국어设置即时生效。Mac 的“设置”位于屏幕顶部系统应用菜单，快捷键为 `⌘,`；非 Mac 提供窗口内设置入口与 `Ctrl+,`。
- 素材与离线测试草稿纳入统一保存流程；无效输入保留并提示，不能因切换、保存或撤销静默丢失。模态框阻挡背景操作，支持确认／取消及输入法候选保护。
- Windows 自动恢复能识别已退出与仍运行的会话，并处理 PID 复用；长路径写入使用规范化后的原子保存路径。已真实验证完整副本、异常退出候选、章节/人物/原项目来源恢复，以及另一个活动实例的目录保护；无效输入和最近一次快照之后的修改仍不保证恢复。

Swift 外壳与原生 Liquid Glass 尚未完成。当前浅色面板和正常系统标题栏不等于玻璃效果验收。

## 战斗能力：只到已验证的底层接口

当前战斗节点会编译到《活侠传》原版接口：

- `enemy`：`ModifyEnemyTeam` / `ModifyEnemyLevel` / `ModifyEnemyPeople` / `ModifyEnemyId`；
- `battle_skill`：`SetPlayerBattleSkill` / `SetBattleSkillActive` / `ResetBattleSkill`；
- `goto_scene`：只用于普通场景跳转，不再向作者暴露 Combat / Battle 场景预设。
- `combat`：人物只决定姓名与四类动画；背景从官方 `views` 独立选。对手 HP、气力、六维、评语、技能、天赋和行动概率由节点填写。赵活的 `player_*` 覆盖写入本场 Combat 基准值，生命仍先按原版 `GameStat.FinalValue`（含体力和被动）结算，再叠加 `player_max_health`，不会覆盖原版加成或重复累加。无独立四帧时回退 normal 立绘并钉在官方待机中心。胜负来自 `CombatManager.GameOver(bool)`。
- `battle`：每个附加阵营单独设人数，该方总人数 = 阵营人数 + 具名角色。可选 `title`（`ReadyPanel`）、`friend_health` / `enemy_health`（克隆 `HealthData`）。具名角色必须能对应原版可生成 preset 或 catalog 里已核实的 Battle Animator。不暴露地图、中立路人和技能预设。
- `battle_result`：按包完整 SHA-256、剧情 id 和可选 Combat/Battle 类型读取 Host 的最后真实结果，只提供已验证的 win/lose 分支。
- `reward`：把现有 `stat` / `affinity` / `talent` / `item` / `flag` 原子接口聚合为 1~32 项奖励。
- `result_screen`：用原版 `mainui.DisplayMessageText` 显示作者填写的结算标题与说明，再逐项执行与 `reward` 相同的现有奖励接口；不创建新的结算 UI。
- `custom_shop`：临时替换原版 `ShopDatabase` 的书籍、杂物、贵重品库存并复用 `ShopPanel`；支持数量、MOD/原版条件和原版统一折扣，关闭或故障时恢复原库存。原版没有公开逐商品价格接口，因此不支持 `price`。
- `stat_check` / `affinity_check` / `item_check` / `talent_check` / `flag_check`：分别读取原版属性、好感、物品、天赋与 MOD/原版旗标后走成功/失败分支；好感、物品、天赋只使用已验证的只读 Host bridge。

接口证据见 [游戏 API 笔记](../../research/gameplay_api.md) 与 [契约片段](../../research/gameplay_api_contract.json)。战斗节点编排原版系统，结果分支目前支持 `win`／`lose`。

新 `addon/sandbox` 模式支持在章节中使用属性、好感、物品、旗标和时间步骤；跨事件任务和持久变量由「剧情安排」管理。旧 `mod_quest/persistent_var` 节点保留兼容用途。

## MOD 战役状态

- `mod_quest` / `quest_check` 提供按包完整指纹隔离的任务状态机；它不调用、不污染原版 Mission 系统，并在同一 MOD 战役会话内跨 Story / Free 保留。
- `persistent_var` / `persistent_check` 提供 Int32 持久变量：只允许当前 MOD 的 `mod_campaign_<campaign_id>` / `_sNNN` 隔离手动槽，Host sidecar 与稳定战役身份绑定，并在原版手动/自动存档成功返回后原子落盘；不修改 GameSave schema。缺失值为 0，每包最多 256 项。
- `modflags` / `modvars` 仍是 Story 会话表，不写存档；需要跨重启保存的数值应显式使用 `persistent_var`。

## 尚未实现

- 自定义商店的消耗品库存栏或逐商品自定义价格；当前 `custom_shop` 严格限于原版 `ShopPanel` 实际展示的三类库存及统一折扣。消耗品本身可作为作品素材创建、取得和使用。
- `mod_quest` 跨重启持久化，以及任意 Lua 对象和字符串持久化；普通/F5 官方槽始终不会写入 MOD sidecar。
- 自定义战斗地图、模型、AI 或完整战斗引擎。
- 联网社区内容库、自动上传或发布。

若功能依赖尚未由反编译和实机验证确认的游戏结果或生命周期接口，应先研究并记录结论；不以猜测 API 的方式补齐。

## 验证范围

当前能力不等于每种素材、分支、第三方 MOD 组合和显示比例都完成实机验收。编辑器模拟、纯舞台出图、原生视频和真实玩法测试各有范围；性能结果也仅对应发布记录中的机器与工程条件。

本次验证范围见 [测试入口](test_matrix.md)，历史版本记录可查 [GitHub Releases](https://github.com/mohui666/lom_modkit/releases)。支持的旧工程和包仍可打开并编辑，新导出使用当前生成器；不会因升级要求作者重建作品，来源／Lua 安全检查继续保留。
