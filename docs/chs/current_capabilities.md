# 当前能力与边界

本文对应 **1.5.15**。Rust 编辑器与编译器提供 73 类节点，C# `MortalModHost` 接入游戏，包／剧情／内容契约为 **3 / 2 / 1**。更新见 [本版说明](../../RELEASE_NOTES_v1.5.15.md)，操作见 [软件使用](software_usage.md)。

MOD 智能自动播放使用游戏的自动按钮，从文字显示完成后按有效字数计算阅读时间；有语音时等待结束并保留 0.3 秒。个人速度三档、菜单／日志暂停、手动继续、快进和选项等待已在隔离游戏配置与测试存档中做过定向实测；接口和范围见 [API 实证](../../research/gameplay_api.md#2026-11-09-mod-智能自动播放)。需要 Host 1.5.3。

- 步骤可勾选、Ctrl 点选或 Shift 连选，批量拖动时靠近列表上下边缘自动滚动；支持整组选中步骤上移、下移、移到最前或最后。
- 对白模式位于表单最上方。“画外音（无立绘）”默认显示“？？？”，支持自定义姓名，不加载人物立绘。
- “修改姓名与称号”节点统一支持赵活、其他原版人物和自定义人物；姓名与称号可分别保持、设置或恢复，称号另外支持隐藏。跨章生效并随当前作品存档保存。称号功能需要 Host 1.5.4，自定义姓名需要 Host 1.5.5。
- 压暗支持持续保持、下一句对白恢复自动和立即恢复自动；旧步骤保留持续设置。画外音与新压暗方式需要 Host 1.5.1。

- 默认每 5 分钟自动保存到当前项目，可在设置中关闭或调整间隔；新项目和恢复载入副本需先手动保存。保存同步执行，目录项目通常比重新压缩包更快；完整限制见 [保存与恢复](editor_recovery.md)。
- 回忆、黑白、梦境、火光、模糊变暗支持色调与二维模糊／暗角近似预览及渐变；中途试玩恢复可达路径上的独立滤镜开关和人物渲染选择。真实景深、颗粒和任意 Lua 动态状态不保证模拟。
- 全人物清场支持可选淡出时长，正时长需要 Host 1.4.15；留空或 0 保持立即退场。

- 对白可设置本句气泡、临时隐藏或跟随人物表情，结束后恢复此前气泡和偏移，需要 Host 1.4.10。
- 旧版预览素材根据原版 Sprite 画布和裁切偏移校正人物比例。作品立绘与表情支持基准图叠加、一键对齐及人工微调。
- 画面调整支持人物、图片和气泡的拖动、缩放、吸附、方向键微调及布局复制。校准和布局随作品保存。
- 气泡按动画帧时间刷新，小图片保留原始分辨率，纹理缓存按内存限额回收。特效预览缓存路线计算，长步骤列表只绘制可见行。
- 滤镜渐变预览复用已解码原图、滤镜端点和动态纹理；中间帧对同源RGBA做近似插值，透明边缘与加色像素保持，不在每个权重重新解码或新建纹理。首次端点计算仍同步进行；静态起终态沿用原有色彩／模糊计算，二维预览不等于游戏URP渲染。
- 屏幕特效使用本机游戏渲染的缓存帧，支持百分比坐标、横纵缩放、翻转、旋转、速度、定时停止、叠加、标记和重播。具体操作及采样限制见 [特效预览](software_usage.md#特效预览与控制)。

## 原版剧情与系统

从本机游戏导入原版章节，可修改片段或整章，插入条件剧情和演出。原版调用和赋值转为结构化指令，条件分支保留成立、不成立及汇合去向，局部变量保持作用域。旧整章项目可升级来源结构，新增战斗跨场景续接受局部状态限制。

游戏中按 `Ctrl+F6` 标记章节与对白，编辑器通过「文件 → 原版剧情 → 原版路线图…」或「打开最近游戏标记」定位。静态路线来自本机任务与脚本，动态去向结合当前游戏会话中实际捕获的临时槽和跳转。未受修改影响的原版步骤隐藏 MOD 标识，新增、改写与持续影响保留标识，来源判定按章缓存。

数值、好感、物品、天赋和奖励等操作可开关系统提示。心上人可按人名选择，结束剧情按自定义章节名选择去向。编辑器启动时自动同步已安装的 Host。

## 当前桌面界面

- Rust／egui 浅色通用外壳，保留左侧章节和步骤、中间属性、右侧预览三栏；标准标题栏显示作品名称与未保存状态。
- 章节支持分组、折叠、改名和移动。新建分组会将当前章节归入该组。步骤小字优先显示节点备注，未填写时显示节点 ID，并保留原有概要。新建／复制章节和素材导入使用独立命名窗口。
- 可选字段直接显示语义明确的默认值，不再用“启用字段”复选框作为入口；内部步骤／章节标识改名放在“编辑 → 高级”。真正的布尔选项仍使用复选框。
- 人物字段直接输入搜索，下方显示可选结果；选择后才写入底层 ID，取消搜索保留原值。同名不同 ID 的数字在搜索前后稳定。作品内容库按有边框的独立行显示名称、右侧类型和选中状态。
- 默认表情、无语音、默认对话模式分别清除对应可选字段；默认对话仍显示人物姓名，用户人物使用其内容名称。流程图按分支、汇合和回路布局，支持缩放、适应宽度、节点点击及选中定位；可识别节点的编译错误链接会定位到该步骤。
- 简体中文、繁體中文、日本語、한국어设置即时生效。Mac 的“设置”位于屏幕顶部系统应用菜单，快捷键为 `⌘,`；非 Mac 提供窗口内设置入口与 `Ctrl+,`。
- 素材与离线测试草稿纳入统一保存流程；无效输入保留并提示，不能因切换、保存或撤销静默丢失。模态框阻挡背景操作，支持确认／取消及输入法候选保护。
- Windows 自动恢复能识别已退出与仍运行的会话，并处理 PID 复用；长路径写入使用规范化后的原子保存路径。已真实验证完整副本、异常退出候选、章节/人物/原项目来源恢复，以及另一个活动实例的目录保护；无效输入和最近一次快照之后的修改仍不保证恢复。

Swift 外壳与原生 Liquid Glass 尚未完成。当前浅色面板和正常系统标题栏不等于玻璃效果验收。

## 战斗能力：只到已验证的底层接口

当前战斗节点会编译到《活侠传》原版接口：

- `enemy`：`ModifyEnemyTeam` / `ModifyEnemyLevel` / `ModifyEnemyPeople` / `ModifyEnemyId`；
- `battle_skill`：`SetPlayerBattleSkill` / `SetBattleSkillActive` / `ResetBattleSkill`；
- `goto_scene`：只用于普通场景跳转，不再向作者暴露 Combat / Battle 场景预设。
- `combat`：人物只决定姓名与四类动画；背景从官方 `views` 独立选。对手 HP、气力、六维、评语、技能、天赋和行动概率由节点填写。赵活的 `player_*` 覆盖写入本场 Combat 基准值，生命仍先按原版 `GameStat.FinalValue`（含体力和被动）结算，再叠加 `player_max_health`，不会覆盖原版加成或重复累加。无独立四帧时回退 normal 立绘并钉在官方待机中心。胜负来自 `CombatManager.GameOver(bool)`。
- `battle`：每个附加阵营单独设人数，该方总人数 = 阵营人数 + 具名角色。可选 `title`（`ReadyPanel`）、`friend_health` / `enemy_health`（克隆 `HealthData`）。具名角色必须能对应原版可生成 preset 或 catalog 里已核实的 Battle Animator。不暴露地图、中立路人和技能预设。
- `battle_result`：按包完整 SHA-256、剧情 id 和可选 Combat/Battle 类型读取 Host 的最后真实结果，只提供已验证的 win/lose 分支。
- `reward`：把现有 `stat` / `affinity` / `talent` / `item` / `flag` 原子接口聚合为 1~32 项奖励。
- `result_screen`：用原版 `mainui.DisplayMessageText` 显示作者填写的结算标题与说明，再逐项执行与 `reward` 相同的现有奖励接口；不创建新的结算 UI。
- `custom_shop`：临时替换原版 `ShopDatabase` 的书籍、杂物、贵重品库存并复用 `ShopPanel`；支持数量、MOD/原版条件和原版统一折扣，关闭或故障时恢复原库存。原版没有公开逐商品价格接口，因此不支持 `price`。
- `stat_check` / `affinity_check` / `item_check` / `talent_check` / `flag_check`：分别读取原版属性、好感、物品、天赋与 MOD/原版旗标后走成功/失败分支；好感、物品、天赋只使用已验证的只读 Host bridge。

接口证据见 [游戏 API 笔记](../../research/gameplay_api.md) 与 [契约片段](../../research/gameplay_api_contract.json)。战斗节点编排原版系统，结果分支目前支持 `win`／`lose`。

新 `addon/sandbox` 模式支持在章节中使用属性、好感、物品、旗标和时间步骤；跨事件任务和持久变量由「剧情安排」管理。旧 `mod_quest/persistent_var` 节点保留兼容用途。

## MOD 战役状态

- `mod_quest` / `quest_check` 提供按包完整指纹隔离的任务状态机；它不调用、不污染原版 Mission 系统，并在同一 MOD 战役会话内跨 Story / Free 保留。
- `persistent_var` / `persistent_check` 提供 Int32 持久变量：只允许当前 MOD 的 `mod_campaign_<campaign_id>` / `_sNNN` 隔离手动槽，Host sidecar 与稳定战役身份绑定，并在原版手动/自动存档成功返回后原子落盘；不修改 GameSave schema。缺失值为 0，每包最多 256 项。
- `modflags` / `modvars` 仍是 Story 会话表，不写存档；需要跨重启保存的数值应显式使用 `persistent_var`。

## 尚未实现

- 消耗品目录或逐商品自定义价格；当前 `custom_shop` 严格限于原版 `ShopPanel` 实际展示的三类库存及统一折扣。
- `mod_quest` 跨重启持久化，以及任意 Lua 对象和字符串持久化；普通/F5 官方槽始终不会写入 MOD sidecar。
- 自定义战斗地图、模型、AI 或完整战斗引擎。
- 联网社区内容库、自动上传或发布。

若功能依赖尚未由反编译和实机验证确认的游戏结果或生命周期接口，应先研究并记录结论；不以猜测 API 的方式补齐。

## 1.4.19 验证范围

统一错误组件覆盖窗口与内嵌错误，核对现有 267 个校验错误样例，并补充文件、下载、共享库、游戏组件及后台任务的处理提示和回归。原版此前拒绝的 10 项随机音效共 45 个实际分支已核对并解码，Windows 播放器与缓存清理回归通过；实时状态、总线效果与尚不支持的混音仍以游戏为准。

隔离游戏配置和测试存档中，原版与自定义人物的震动／移动／位移＋气泡共六组通过；原版与自定义书页图的淡入、零时长／省略时长立即显示及隐藏清理通过。使用实际 1.4.14 编译器样例验证音效、气泡、书页和原有旧包的打开、编辑、保存／导出、重开与原文件保留，任意替换脚本仍被拒绝。

Windows 配套组件随 exe 内置和更新，资源提取改用 Rust；书页正数淡入要求 Host 1.4.19。未复现反馈者偶发 UI 消失或原工程声音／气泡丢失，不声称解决这些未复现反馈；未重新实测 macOS GUI、第三方 MOD 组合或全部 Combat／Battle 分支。

本机对照 2200 个章节路线和 2035 张输出图片，图片尺寸、人物／表情目录及气泡帧、时间、循环点和位置一致；图片缩放存在细微像素差异，抽查差异最大的结果未发现明显变化。单 exe 在独立缓存与不同启动目录下完成全量素材提取、13 项音频试听／停止／取消、项目导出重开与游玩包导出，缺失提取器缓存可自动补齐。发布版 Rust 程序静态链接 VC 运行库；不携带 Python 环境，音频解码继续使用内置的原生 vgmstream。

历史版本的验证记录见 [GitHub Releases](https://github.com/mohui666/lom_modkit/releases)。
