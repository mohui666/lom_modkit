# 软件使用文档

本页说明如何使用编辑器；脚本字段与节点契约请查 [脚本 / API 文档](script_reference.md)。编辑器内也在“帮助 → 文档”中把两类内容分成独立页签。

## 基本流程

1. 新建或打开项目，在左侧组织章节和步骤。
2. 在中间表单编辑当前节点；官方 ID 下拉会显示可读名称，保存时仍写稳定 ID。
3. 用右侧预览、流程图和 `F6` 体检确认剧情；发布前再用 `Ctrl+F6` 严格体检。
4. `F5` 生成隔离的临时试玩包；“导出 Mod”生成正式 `.lommod`。
5. 用户音频、图片和自定义角色统一从“用户内容”导入；先选内容类型，再填写该类型字段。试听只在音频被选中时显示。

## 战斗与战役

- “决斗（Combat）”编排一对一原版 Combat：人物字段只决定本次对手动画；血量、体力、属性、绝招、天赋与行动概率均由节点显式设置，未填写时不从所选人物继承。
- “战役（Battle）”编排多人原版 Battle：分别选择我方/敌方阵营、总人数与官方具名人物。总人数已经包含具名人物，不能额外重复计数。
- 两者只复用已反编译确认的原版接口；不创建地图、模型、AI、动画或新的战斗引擎。

## MOD 战役读档与隔离

标题画面的“开始 MOD 战役”复用原版读档面板。先选择战役，再进入该战役自己的主档、自动档与新建入口；选择本身不会直接开局。

- 原版手动槽：`001`～`020`；MOD 手动槽：`mod_campaign_<campaign_id>`。旧 `mod_<mod_id>` 不会被探测或迁移。
- MOD 自动槽追加 `_auto`、`_auto_free`、`_auto_battle`；绝不写原版 `auto*`。
- 保存 MOD 时，Universe 最近槽仍保持最后一个原版槽；原版“继续游戏”不会跳进 MOD。
- MOD 持久变量 sidecar 按稳定 `campaign_id` 隔离，并记录包 id 与完整 SHA-256 供核对；同一战役更新包须保持 `campaign_id` 不变。

## 来源标记

MOD 演出有固定全局来源载体；对白框正文下方居中显示高可见度半透明单行标记，不覆盖文字，结局、死亡与人物介绍卡也有局部标记。运行时会持续修复；无法维持时停止 MOD 并回安全场景。它用于标明“非官方内容”，不是作者签名。
