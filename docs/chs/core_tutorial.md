# 核心功能完整教程：只使用编辑器

本教程面向当前 Windows Rust 编辑器与 Host 1.1.3 配套版本。目标是在软件内完成“创建作品 → 编写演出 → 配置事件与任务 → 检查 → 保存、导出与重开”。全过程不启动游戏、不安装 MOD。右侧“播放”是软件预览；顶栏“试玩”／F5 会安装临时包并启动游戏，本教程不点击。

[播放中文演示](https://github.com/mohui666/lom_modkit/releases/download/v1.3.0/lom_modkit-v1.3.0-core-tutorial-zh-CN.mp4) · [下载跟做项目](https://github.com/mohui666/lom_modkit/releases/download/v1.3.0/lom_modkit-v1.3.0-tutorial-follow-along.zip) · [独立字幕](https://github.com/mohui666/lom_modkit/releases/download/v1.3.0/lom_modkit-v1.3.0-core-tutorial.zh-CN.srt)

录屏使用独立的教程项目与设置目录。中文讲解和字幕说明每一步的目的；打开随附示例的部分会明确标注，不把预先准备好的内容冒充现场创建。视频剪去等待和重复输入，保留实际软件操作。

## 1. 选择作品模式

打开“文件”：

| 入口 | 适合的作品 | 软件中的区别 |
| --- | --- | --- |
| 新建原版附加剧情 | 在原版流程中插入自己的剧情 | 事件从日期或地点触发，没有自己的开场战役 |
| 新建自由剧本 | 从自己的开场开始 | 自动创建开场事件；游戏侧使用自己的隔离存档 |

先用“新建原版附加剧情”。点作品名旁“作品设置…”，填写名称、版本、作者、简介；高级编号不需要为普通创作修改。两种模式的完整字段见 [事件与任务配置](events_and_tasks.md)。

## 2. 看懂工作区

四个一级入口是“剧情编辑”“素材管理”“游戏与 MOD”“发布”。

剧情编辑保留三栏：左侧选择内容，中间编辑所选内容，右侧预览或查看关联。左侧“剧情内容”负责对白、选项和画面，“剧情安排”负责事件及可选任务。作品设置属于整部作品，不属于某个章节或步骤。

章节下拉旁“＋ → 新建章节…”填写可读名称；内部标识自动生成。用“复制当前章节…”复用已有演出。也可以直接打开 [原版附加剧情示例](../../samples/event-addon/) 跟做后面的送信流程；[自由剧本示例](../../samples/event-sandbox/) 另有开场。

## 3. 写对白并预览

选中左侧“对白”，在中间输入台词。先用旁白完成最小剧情；配置了人物时，选择对应模式、外观和表情。右侧“开头／上一步／下一步”逐步检查，“播放”用于软件内演示。手动选择其他步骤会停止播放。

选项分支中的文本供玩家选择，目标步骤决定接下来走哪条线。切到右侧“流程图”观察分支与汇合；点击图中节点返回对应表单。结束步骤的 `event_result` 决定该次事件采用哪个结果；示例的“接下信件”和“婉言拒绝”分别关联接受与拒绝结果。

教程先修改示例的一句台词、人物和表情，再检查选项、画面与流程图。软件预览不等于游戏里的选择、存档或奖励已执行。

## 4. 导入自己的素材

1. 进入“素材管理 → 作品素材 → 导入素材…”。
2. 选择图片、角色、音乐、音效或配音，选择本机文件，再确认可读名称。
3. 角色第一张立绘作为默认；可以继续追加表情。中文或数字文件名会自动分配合法编号，不必改动原文件。
4. 回到剧情步骤，通过资源选择器选刚才的素材；导入并不自动让人物登场。

背景、CG 和前景都使用图片素材，人物使用角色素材。教程素材使用项目自有图片。官方预览素材可另从自己的游戏只读提取；本教程不触发游戏提取或安装。文件限制与共享库见 [用户内容](user_content.md)。

## 5. 安排一个日期事件

进入“剧情安排”，选择“七月来信”。按需要修改：

- 年／月／旬：例如第 2 年、7 月、上旬。游戏没有逐日的“几号”。
- 怎样遇到：时间到了自动发生，或前往某个地点。
- 播放哪段剧情：选择中文章节标题。
- 发生概率：教程使用 100%，便于理解；示例原值 30% 可以保留作对照。
- 可以重复发生：不勾选表示成功播放后不再发生；勾选后选择行动、旬或月的间隔。

一次性事件没有发生时，后续周期仍可再尝试。判定记录随事件状态保存；不要把编辑器配置或静态体检说成游戏触发已经验收。

## 6. 让事件推进任务

示例的“替同门送信”关联两个事件：

1. 七月来信：在“剧情结束后做什么（可选）”查看接受／拒绝选择分别把任务推进到什么状态。
2. 山门交信：前置任务要求已接取，界面地点为“大门”；正常结束后把任务改为已完成，并可配置奖励。

点右侧“关联任务”进入任务表单，查看开始状态及可选自动转换；再点“关联事件”返回事件。菜单显示中文名称和状态，内部编号放在高级设置。只有跨事件记录进度时才需要任务，普通日常事件可以独立存在。

时间、属性修改、任务推进和奖励放在事件条件／结果动作中；新模式不会在章节添加菜单里显示旧版的所有状态修改节点。全工具共 64 类节点，新模式演出菜单是其中的适用子集。

## 7. 配置可重复日常

选择“练功闲谈”：它在练功场按每次行动判定，可以重复；“平常练功”是同组的另一候选。高级设置中可查看事件池及权重。30:70 表示候选均满足条件时的相对抽取权重，不是两个独立发生百分比。

先把常规日期、地点、重复和间隔设置清楚；确有需求再展开编号、条件树、权重及完整结果动作。重复事件不要意外把已经完成的任务重设为进行中。

## 8. 检查、保存和导出

1. 可按 F6 查看章节校验与当前章节的 Lua 编译结果，修复可定位到步骤的问题；视频使用下面的完整作品体检。
2. 进入“发布 → 发布体检与打包”，做“编辑体检”及“发布体检”。完整体检才检查 Manifest、事件／任务与发布信息。
3. 用 Ctrl+S 保存全部。新模式请保存到项目目录，其中有 `manifest.json`、`scenario.json`、`story/` 和已使用素材。
4. 点“发布 → 导出 .lommod…”或顶栏“导出 Mod”，选择输出 `.lommod`。它会重新编译并包含实际引用素材。
5. 在“发布 → 包检查与水印检测”检查导出的包，再用“文件 → 打开 JSON / Mod 包…”重开，核对章节、事件、任务和素材。

生成本地包或发布目录都不会自动上传。技术详情和 CLI 可用于核对源码／Lua 一致性，但不执行游戏逻辑。

## 9. 安全结束与常见提示

自动恢复约每 30 秒记录未保存修改，仍应主动保存。弹窗右上关闭和 Esc 取消当前操作；关闭未保存提示保留编辑，关闭恢复提示保留副本。不要把“移除副本”当成关闭按钮。

“安装／更新 C# 宿主”的 `changed:false` 表示所选源目录与游戏里已有的两个 DLL 相同。它不是互联网最新版本证明；应选择完整新编辑器旁的 `runtime`。本教程仅讲明这类提示，不进行安装或 F5 试玩。

完成教程后得到可继续编辑的项目目录和导出包。游戏里的事件触发、任务推进、奖励及存档读档需要另行实测；本视频只证明展示过的软件操作。
