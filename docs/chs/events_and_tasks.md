# 事件与任务配置

事件／任务的基础功能要求 MortalModHost 1.1.3；1.5.10 新增的原版章节入口事件要求 Host 1.5.10。作品级设置与剧情内容分开编辑。

## 两种作品

| 模式 | 新建入口 | 运行方式 |
| --- | --- | --- |
| `addon` 原版附加剧情 | 文件 → 新建项目 → 新建原版附加剧情 | 在原版存档流程中按条件触发，保留原版任务优先顺序，不创建独立战役 |
| `sandbox` 自由剧本 | 文件 → 新建项目 → 新建自由剧本 | 从标题页进入隔离存档，使用自己的开场事件，可以禁用原版事件 |

旧作品没有 `play_mode`，仍走旧 v3 战役契约，不自动重写旧任务、旗标或章节。附加剧情不参与其他 MOD 的战役；独立作品只调度当前作品的事件。多个附加包依现有文件名加载顺序匹配，各包事件池和状态独立。

已有事件模式工程可在「作品设置 → 作品玩法 → 转换为」切换玩法。自由剧本转为附加剧情时，先为原开场事件选择自动触发或地点触发，再执行转换；章节、素材、任务、事件 ID 和作品身份保留。附加剧情转为自由剧本时，选择开场章节，编辑器新增专用开场事件，保留原普通事件的条件与结果。两种玩法使用各自的存档入口，转换工程不迁移已有游戏进度。

自由剧本的「作品设置 → 开场入口」同时显示开场事件、开场章节与作品入口。更改开场章节会同步两处关联；已有工程出现 `entry_event` 与 `manifest.entry` 不一致的报错时，选择正确开场后点击「关联并同步入口」。缺少开场事件时，可直接「创建开场事件」。

## 配置与保存

`manifest.json` 保存作品身份、`play_mode`、兼容性与开局设置；独立的 `scenario.json` 保存事件和任务；`story/*.json` 保存演出章节。

作品名旁的“作品设置…”（或文件 → 作品设置）管理整部作品。左侧“剧情内容”编写对话、选项和演出；“剧情安排”列出事件，下面的“任务进度（可选）”记录跨事件流程。选中一项后，中间只编辑该项，右侧显示关联剧情或事件。

事件的时间条件可选精确／每年日期、从日期起、截至日期或日期范围，再选择触发入口、剧情、概率与是否重复。游戏没有逐日日期，日期以年、月、上／中／下旬表示。起止范围包含所选旬，按完整日期比较，跨年仍有效。“前置任务”和“剧情结束后做什么”可选；编号、条件树、权重池及完整结果动作放在高级设置。

例如“七月来信”：时间选不限年份、7 月、不限旬；自动发生，30% 概率，不重复，每月再尝试。只想固定在第 2 年 7 月上旬发生，就分别选择第 2 年、7 月、上旬。剧情下拉框显示作品内的标题，内部仍保存原章节 ID。

例如“第 2 年 3 月之后可发生”：选择「从日期起」，填第 2 年、3 月、上旬，表示从该旬起始终可触发。如果要求整个 3 月结束后才开始，则填第 2 年、4 月、上旬。不要分别设置「年份 ≥ 2 且月份 ≥ 3」，那会错误排除下一年的 1～2 月。日期范围保存为既有 `all/any` 时间条件，不增加游戏日期字段，也不重写作者的其他复杂条件。

高级条件中的「全部满足（并且）」与「任一满足（或者）」切换时保留原有子条件与嵌套层级。「添加条件组」建立嵌套组合；单项比较可用「组合条件…」包入条件组或反转，已有时间条件会保留。

这两类配置分别编辑 `scenario.json` 的 `events` 和 `tasks`。配置随作品一起保存、撤销、恢复、导出和重新导入。带配置的作品必须保存为项目目录或 `.lommod`，不能另存成单一章节 JSON 而丢弃配置。

「添加步骤 → 属性与旗标」也可在新模式中使用：属性增减/设置、好感、天赋、物品、剧情旗标、游戏任务旗标、子任务和时间步骤，均在抵达该步骤时执行。可把开场所需的时间、属性和物品放在开场章节前部。事件触发条件、跨事件变量和任务进度继续由「剧情安排」管理；`mod_quest`、`persistent_var` 等旧任务状态节点仍不混入新模式。

`manifest.play_mode` 为 `addon` 或 `sandbox`，`min_host_version` 至少 1.1.3。保留 v3 稳定 `campaign_id`：附加剧情只用它区分自己的存档状态，不创建 MOD 槽。附加剧情的 `campaign.new_game=false`，自由剧本为 true。新模式不能混用 `campaign.triggers`。

## 事件

顶层配置为 `{"schema":1,"events":[],"tasks":[]}`。自由剧本另有 `entry_event`，指向唯一开场事件，其章节与 `manifest.entry` 一致。

| 字段 | 含义 |
| --- | --- |
| `id`、`name` | 稳定事件 ID 与显示名称 |
| `trigger` | `start` 开场、`auto` 自动触发、`position` 点击唐门地点、`story_entry` 进入原版章节前 |
| `position`、`script` | 地点 ID（仅地点事件）和同包演出章节 ID |
| `target`、`from` | `story_entry` 的原版目标章节 ID；可选 `from` 限制来源原版章节 |
| `enabled` | 是否启用，默认 true |
| `once` | 默认 true，完成演出后不再发生；false 表示可重复 |
| `check` | `month` 每月、`stage` 每旬、`action` 每次行动；默认每旬 |
| `priority` | 越大越优先，同优先级按配置顺序 |
| `chance` | 0～100 的实际发生概率，默认 100，允许小数 |
| `pool`、`weight` | 可选事件池和相对权重；默认权重 1 |
| `weight_modifiers` | 按条件增减权重，最低归零 |
| `when` | 组合条件；`{"all":[]}` 表示不限制 |
| `outcomes` | 演出结果与结算配置，必须包含 `completed` |

重复性与判定周期分别设置。`once=false, check=action` 可在同一个月多次发生；`once=false, check=month` 每月可以重新发生。一次性事件概率失败后，下个判定周期仍可再试；完成演出后退出候选池。

未抽中也消耗当前状态中本周期的判定；反复进出场景不会重抽。判定记录随存档保存：读取已经包含判定记录的存档会保留该结果，读取判定发生前的旧存档会恢复当时状态，不能宣称无条件防止反复读档重抽。行动周期使用“年、月、旬、剩余行动次数”；事件不额外扣点，地点行动沿用原版扣点流程。

同池候选必须使用相同入口、地点／目标及来源、优先级和周期。先筛选条件，再判定各候选的 `chance`，最后按正有效权重抽取一项，参与判定的候选消耗本周期机会。权重 30:70 表示双方符合条件时按这个比例抽取，不是两个独立百分比。

### 原版拜访与章节入口

「剧情安排」选中事件，在「怎样遇到」选择「进入原版剧情时」，设置「原版目标章节 ID」，再选择要播放的本作品剧情。目标可从当前安装游戏的原版章节目录搜索选择；勾选「限制来源原版章节（可选）」时，仅在指定来源进入目标时触发。省略来源表示任何进入该目标的路径都可满足条件。

这是一种通用的章节入口规则，可叠加日期、任务、旗标、好感等既有条件。当前「去某地点时」对应唐门地图的地点；外出拜访使用原版章节入口，不能把背景名或锻造活动编号当作拜访入口。

例如从崆峒地图拜访铁拳门：目标为 `section_01_free_03`，来源为 `section_01_free_start_02`。时间选择「从日期起 → 第 2 年 3 月上旬」，选择自己的演出章节，概率 100%，不勾选重复发生，即可配置为满足日期后的首次该次拜访发生。样例见 [原版附加剧情](../../samples/event-addon/)。代码按所选章节 ID 调度，没有写死铁拳门规则。

事件在原目标章节开始前插入；普通结束节点结算事件后继续进入原目标，不重新执行地图选项或再扣一次拜访行动力。它不保存任意 Lua 调用栈；依赖上章人物现场的中间章节，应选择其能初始化场景和人物的正式入口。原版目录展示的是章节，不能把所有章节都当作独立地图地点。

## 条件与任务

组合条件使用 `all/any/not`，最多 12 层；空 `all` 为真，空 `any` 为假。叶条件示例：

```json
{"source":"time","key":"month","op":"eq","value":7}
```

来源支持 `time/stat/affinity/flag/game_flag/variable/task`。时间字段为 `year/month/stage/action`；`flag` 是剧情记录是否存在（0/1），`game_flag` 是原版数值旗标，`variable` 是作品自有 Int32 变量（缺省 0）。任务状态支持 `eq/ne`，数值支持 `eq/ne/lt/le/gt/ge`。缺失原版属性或旗标明确报错，不能在 NOT 条件下变成成功。

原版数值旗标现在以中文用途显示，可搜索人名、地点、用途和原始代号。选中后显示原版开发备注；有明确数值说明时可直接选择中文状态，如「留学去向 → 青城（1）」。没有列出的数值仍可手填，不会自动改写旧值。「增加」动作填写增量，不套用状态选项。临时暂存旗标单独提示原版复用风险，未有说明的代号归入高级选项。关联章节按脚本的直接读写引用列出，点击在独立窗口只读查看调用和对白，不切换当前作品。工程和导出包始终保存原 ID 与数值，名称说明不参与游戏判断。

目录按当前游戏任务管理器实际注册的旗标集合补齐，包含没有出现在旧脚本扫描结果中的项目。用途与数值说明来自原始开发备注；没有备注的项目仍显示用途未确认，不推测默认 0 或其他数值的含义。例如 `M00032` 为「崆峒留学·瑞笙参战」，与 `M50010`「迎战崆峒·瑞笙参战」分别保留。

任务定义 `id/name/states/initial`，可选 `transitions`。每次调度基于同一任务状态快照，每个任务最多执行一个条件转换；随后事件读取更新后的状态。

任务页的「可用状态（勾选）」提供未开始、可接取、进行中、已接取、已完成、已拒绝、已失败及已取消等选项，无需手输 `accepted`。初始状态、状态转换、条件和结果中的任务状态统一从该任务的可用状态下拉选择；悬停可查看内部编号。旧工程自定义编号保持原值，也能继续选择；新增自定义编号放在「自定义状态（高级）」中。

事件结果也可直接推进任务：

```json
{
  "completed": {
    "tasks": {"delivery":"completed"},
    "variables": {"visits":{"op":"add","value":1}},
    "actions": [{"type":"stat","key":"money","op":"add","value":50}]
  }
}
```

最多 256 个任务（每项 1～32 个状态）、512 条事件。保存的任务状态若已不在修改后的配置中，会报告不兼容，不静默清空。

## 章节与结果

章节保留对白、人物演出、选项、分支和玩法场景，也支持在剧情抵达时修改时间、属性、好感、天赋、物品、旗标与原版子任务。事件登记、跨事件任务推进和持久变量由独立配置管理，新模式仍不使用对应的旧状态节点或 `raw`。旧格式继续兼容。

结束节点填写 `event_result`，例如 `accepted/declined`，不填则为 `completed`。每个最终章节结果都必须在事件的 `outcomes` 中定义。它不能与 `next_script` 同时填写；跨章节演出保留当前事件直到最终回报。

结果动作支持：

- `stat/affinity/game_flag`：`key`、`op=set/add`、Int32 `value`。
- `flag`：`key`，记录剧情标记。
- `talent`：`key`、`value=1/-1`。
- `item`：`key`、`kind=book/misc/special`、`op=add/remove`、正整数 `value`；`remove` 按 `value` 减少数量，使用原版 `AddItem` / `AddCount` 的归零规则。
- `time`：`year/month/stage`，设置明确游戏日期。

宿主先验证结果、原版 ID、变量溢出和最终状态的 128 KiB 编码上限，再执行结果动作并写回任务、变量与完成记录。变量溢出不会部分提交任务。意外的游戏接口异常会中止演出；游戏结果动作没有跨接口整体回滚，不能宣称完整事务。

完整软件操作可参照 [软件使用](software_usage.md)。

状态存于本作品命名空间的 `StoryKeyList/StorySave` 记录，随原版存档读写；不修改 `GameSave` schema 或官方任务资产。未保存的内存变化不等于磁盘存档。F5 单章试玩只预览演出，不携带事件任务配置或发放配置中的奖励，也不模拟原版地图入口。

## 用测试状态验证触发条件

选中非开场事件，在右侧展开「测试触发条件」，设置年／月／旬和该事件使用的属性、好感、原版数值旗标、事件变量或任务状态，再点「用此状态进游戏测试」。不需要原版存档；测试包在固定的编辑器隔离槽重新开局，不修改正式条件或原版存档。游戏处于标题或自由场景后执行，更新 Host 时需重启游戏。普通 F5 继续只预览演出。

测试保留原事件条件、概率与优先级；不会强制命中。默认暂停原版自动事件，便于在没有原版进度时测试；勾选「同时运行原版事件」可检查原版任务优先规则下的结果。地点事件请实际点击对应地点；原版章节进入事件直接进入指定原版章并设置指定来源，跳过此前剧情的执行，所以不是完整原版进度快照。基础属性仍受原版加成影响；剧情记录填0表示新测试局不添加该记录。真实条件判定结果写入 Host 日志。此入口需要 Host 1.5.11。

## 编辑器弹窗

恢复、创建、重命名、导入、帮助和工具结果采用统一的应用内弹窗样式，提供右上角关闭、靠右的底部操作与 Esc 退出。关闭恢复提示只隐藏本次提示，不删除恢复副本；关闭未保存修改提示相当于取消切换，保留当前编辑。这些弹窗由 egui 绘制，系统窗口外框与应用内弹窗分开，不能称为系统原生弹窗。
