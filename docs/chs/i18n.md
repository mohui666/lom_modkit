# 多语言（i18n）

> 语言：简体中文（本文） · [繁體中文](../cht/i18n.md) · [日本語](../ja/i18n.md) · [한국어](../ko/i18n.md)

包括编辑器界面、游戏内 Mod 菜单和作者填写的剧情翻译。界面由 Rust 实现，游戏内菜单由 C# Host 实现；切换编辑器语言不会自动翻译作品正文。

支持语言：简体中文 `chs`（默认/兜底）、繁体中文 `cht`、日语 `ja`、韩语 `ko`。

## 1. 编辑器界面

macOS 从「屏幕顶部系统应用菜单 → 设置」打开设置，或按 `⌘,`。其他平台点窗口中的「设置」或按 `Ctrl+,`。在设置中选择界面语言，立即刷新并记住偏好。Windows 菜单的保存快捷键显示为 `Ctrl+S`；设置快捷键已按 Windows 实际按键事件修复并复测。

当前偏好写入用户数据目录下的 `rust/preferences.json`，键为 `ui_locale`；启动仍兼容读取旧 `settings.json` 的 `language`。不再使用 Qt 翻译包或 Python 刷新界面。

### 1.1 目录结构

```text
editor/i18n/
  locales/<lang>.json  # 界面文案，扁平 key（app.title、menu.file…），缺 key 回退 chs
  terms/<lang>.json    # 游戏名词对照，{类别: {内部id: 译名}}，缺项回退 chs
  help/<lang>.html     # 工具页内嵌帮助文本
rust/lom-editor/
  src/i18n.rs                   # 加载、查询与回退逻辑
  data/native-translations.json # Rust 界面新增文案
```

### 1.2 Rust UI API

`i18n.rs` 提供 `tr`、`key`、`term`、`set_locale` 和 `help_text`。词典、名词表和帮助页在构建时内嵌，运行不依赖 Python；修改这些资源后需要重新构建编辑器。

官方人物、表情、背景、音乐、音效等资源名称通过名词表显示，缺少当前语言时先回退简中，再保留原名称。自定义 `user:` 内容使用作者填写的名称，不自动翻译。

不同 ID 的资源若翻译后同名，选择器显示「名称 1」「名称 2」。编号按完整列表和稳定 ID 计算，搜索不会改变编号；人物的受限列表沿用完整人物目录的编号。作品内容库、章节和分区也会区分同名项。补译和编号只影响显示，不改变资源 ID、作者原名、剧情 JSON、Lua 或语音引用。

人物名称现在可在字段中直接输入搜索，结果显示在输入框下方；选中结果才提交对应 ID，取消不会把检索文字写入剧情。舞台对白使用人物显示名称，包括自定义内容的名称；默认对话模式省略 `mode` 时也保持姓名显示。

人物目录也包含用于演出的道具立绘。它们的名称参与翻译和区分，但不会因此成为有好感数据或战斗能力的人物；对白模式可配台词，语音仍须单独选择。

### 1.3 游戏名词来源与再生成

`tools/extract_i18n_terms.py` 是名词表的维护工具，不是编辑器运行依赖。其主要来源为：

1. **LoM-wiki**（<https://github.com/mohui666/LoM-wiki-CNS>）：人物、门派、
   汗青书/生死簿、属性等优先用 wiki 译名。
2. wiki 没有的条目，回退**游戏解包官方语言表**
   （`lom_unpack/raw/*_zh-cn.txt` / `*_zh-tw.txt` / `*_kr.txt`，
   目录由环境变量 `LOM_UNPACK_DIR` 指定）。

日语条目使用 wiki 与项目补译；缺项使用上述回退规则。当前资源表还包含人工补齐的名称，再生成后应核对这些补译，不能仅以脚本运行成功判定翻译完整。

### 1.4 添加语言

在 `editor/i18n/` 添加界面、名词与帮助文件，在 `i18n.rs` 注册；原生新增文案补入 `native-translations.json`。运行 `cargo test --locked -p lom-editor` 检查嵌入词典，再查看实际界面的名称、字形和同名项。

## 2. 游戏内 Mod 菜单（运行时插件）

`runtime/MortalModHost/src/I18n.cs` 中的 Mod 菜单文案跟随游戏当前语言，读取或匹配失败时回退简中。四种语言的菜单词典内嵌在 C# Host 中；编辑器的界面语言设置不会改变游戏语言。

## 3. 剧情多语言与内部标识

- 「编辑 → 多语言」管理当前章节的正文翻译，独立于界面语言设置。
- 启用剧情多语言后，章节 JSON 保存 `localization`；打包可生成各语言 Lua、文本及 `localization.json`。运行时按游戏语言和作品的回退配置选择，详见 [Mod 格式](mod_format.md)。
- 节点 id、脚本 id、内容 id 等内部标识符不参与翻译。

## 4. 文档多语言

文档架构参考 Docusaurus / Kubernetes 的 per-locale 目录约定：每种语言一个目录，
**简中 `chs/` 是权威版**（改内容先改它），译文同文件名存放：

```text
docs/README.md            # 文档索引（语言导航 + 读者向导）
docs/chs/<name>.md        # 权威版
docs/cht|ja|ko/<name>.md  # 作者向译文（维护者/水印/反编译只留 chs）
docs/research/decompiled/ # 本机反编译归档，gitignore，不上传、不翻译
README.md                 # 简中权威版（GitHub 首页）
README.cht.md  README.ja.md  README.ko.md   # 仓库根译文
```

约定：

- 每篇文档开头有语言切换行，链接按所在目录用相对路径
  （`docs/chs/` 内指向 `../<lang>/`；译文目录内指回 `../chs/`）。
- 译文只译 prose：代码、命令、路径、API/标识符、程序固定输出的错误消息
  保持原文。
- 游戏名词译名以 `editor/i18n/terms/<lang>.json` 为准（与编辑器界面一致）。
- 文档间链接优先指向同语言同目录的译文；该文档无译文时才指回 `chs/`。
- `maintainers.md`、`watermark.md`、`decompiled_api.md` 只维护中文。
- 整份游戏反编译 `.cs` 不得进仓库。只提交自己整理的接口摘要和使用说明。
