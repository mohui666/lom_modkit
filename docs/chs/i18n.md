# 多语言（i18n）

> 语言：简体中文（本文） · [繁體中文](../cht/i18n.md) · [日本語](../ja/i18n.md) · [한국어](../ko/i18n.md)

覆盖两块：**编辑器界面**（`editor/i18n/`，Python）与**游戏内 Mod 菜单**
（`runtime/MortalModHost/src/I18n.cs`，C#）。两者独立实现，互不影响。

支持语言：简体中文 `chs`（默认/兜底）、繁体中文 `cht`、日语 `ja`、韩语 `ko`。

## 1. 编辑器界面

编辑器菜单「语言」切换，偏好存入首选项（`save_pref("language", code)`），
下次启动自动恢复。切换后 `models.refresh_labels()` 刷新节点摘要等文案，
并为 Qt 内置控件（确定/取消等系统按钮）加载对应 `qt_<lang>` 翻译包。

### 1.1 目录结构

```text
editor/i18n/
  core.py            # 加载/查询/回退逻辑（唯一入口）
  locales/<lang>.json  # 界面文案，扁平 key（app.title、menu.file…），缺 key 回退 chs
  terms/<lang>.json    # 游戏名词对照，{类别: {内部id: 译名}}，缺项回退 chs
  help/<lang>.html     # F1 帮助页，缺语言回退 chs
```

### 1.2 Rust UI API

`rust/lom-editor/src/i18n.rs` provides `tr`, `key`, `term`, `set_locale` and `help_text`. JSON dictionaries, term tables and help HTML are embedded at compile time. `rust/lom-editor/data/native-translations.json` contains native UI additions. No Qt translation engine or external Python resources are needed at runtime.

### 1.3 游戏名词来源与再生成

名词对照由 `tools/extract_i18n_terms.py` 生成，优先级：

1. **LoM-wiki**（<https://github.com/mohui666/LoM-wiki-CNS>）：人物、门派、
   汗青书/生死簿、属性等优先用 wiki 译名。
2. wiki 没有的条目，回退**游戏解包官方语言表**
   （`lom_unpack/raw/*_zh-cn.txt` / `*_zh-tw.txt` / `*_kr.txt`，
   目录由环境变量 `LOM_UNPACK_DIR` 指定）。

官方游戏界面只有繁中、简中、韩语，**没有日语**：日语人物名取 wiki 日文页
（汉字与繁中同形），属性名取 wiki 日文设施页译法（脚本内 `WIKI_JA_STATS`
写死）；韩语全文来自官方解包。

### 1.4 Adding a language

Add its locale, terms and help files under `editor/i18n/`, then register them in `rust/lom-editor/src/i18n.rs`. Native labels belong in `native-translations.json`. Run `cargo test --locked -p lom-editor` to validate embedded dictionaries.

## 2. 游戏内 Mod 菜单（运行时插件）

`runtime/MortalModHost/src/I18n.cs`：菜单文案（`entry`/`section.campaign`/
`section.play`/`campaign.start`/`play`/`close` 等 11 个 key）跟随**游戏当前语言**——
通过反射读 LeanLocalization 的 `CurrentLanguage`（读不到时
`GetFirstCurrentLanguage`），语言名模糊匹配（tw/hk/繁→cht，kr/ko/한→ko，
ja/日→ja，其余→chs），四语言目录内嵌在插件里（含日语）。官方游戏本身没有
日语选项，日语目录实际不会触发；检测失败（反射异常、字段改名）一律回退
chs，不影响插件其余功能。

## 3. 注意

- 多语言只影响**界面与菜单文案**；剧情 JSON、`.lommod` 包、Lua 产物不含
  语言信息，玩家用什么语言不影响 mod 内容。
- 节点 id、脚本 id、内容 id 等内部标识符不参与翻译。

## 4. 文档多语言

文档架构参考 Docusaurus / Kubernetes 的 per-locale 目录约定：每种语言一个目录，
**简中 `chs/` 是权威版**（改内容先改它），译文同文件名存放：

```text
docs/README.md            # 文档索引（语言导航 + 读者向导）
docs/chs/<name>.md        # 权威版
docs/cht|ja|ko/<name>.md  # 作者向译文（维护者/水印/反编译只留 chs）
docs/research/decompiled/ # 本机反编译归档，gitignore，不上传、不翻译
README.md                 # 简中权威版（GitHub 首页）
README.cht.md  README.ja.md  README.ko.md   # 仓库根译文
```

约定：

- 每篇文档开头有语言切换行，链接按所在目录用相对路径
  （`docs/chs/` 内指向 `../<lang>/`；译文目录内指回 `../chs/`）。
- 译文只译 prose：代码、命令、路径、API/标识符、程序固定输出的错误消息
  保持原文。
- 游戏名词译名以 `editor/i18n/terms/<lang>.json` 为准（与编辑器界面一致）。
- 文档间链接优先指向同语言同目录的译文；该文档无译文时才指回 `chs/`。
- `maintainers.md`、`watermark.md`、`decompiled_api.md` 只维护中文。
- 整份游戏反编译 `.cs` 不得进仓库。可提交的是我们自己写的接口摘要和哈希。
