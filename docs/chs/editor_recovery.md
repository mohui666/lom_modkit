# 自动恢复

## 自动保存到原项目

编辑器默认每 5 分钟把未保存修改写回当前项目，支持项目目录、单个章节 JSON 和 `.lommod`。在「设置 → 常规 → 自动保存到原项目」可关闭，或改为 30 秒、1 分钟、5 分钟、10 分钟。成功后状态栏显示实际保存位置；设置是个人偏好，不会写进作品。

保存走同步写入，素材较多或重新压缩 `.lommod` 时，界面可能短暂停顿。日常创作建议保存为项目目录，需要发布时再导出压缩包。单个 JSON 不能承载多章节或作品信息修改；出现这类修改时会保留恢复副本，需要手动另存为项目目录。

新项目需先手动保存一次，选择明确的保存位置。恢复载入的副本也需先手动检查、保存一次，之后才自动写回。未完成的素材／测试输入、未保存修改确认窗口或错误窗口存在时，暂不自动写回；原有恢复副本机制继续工作。格式未完成的输入仍不保证能恢复。

自动保存失败会保留未保存状态并提示原因，修改继续留在编辑器中。对项目目录和单个 JSON，保存前会核对上次读取／保存的章节内容；章节已被另一个窗口或外部程序修改时，不用旧窗口内容覆盖它，应先另存当前修改再核对版本。这个检查不是多文件事务，也不保证恢复尚未写入磁盘的内容。

## 本地恢复副本

原生 Rust 编辑器在项目有未保存修改时，约每 30 秒更新一次本地恢复副本，不覆盖原项目。副本包含章节 JSON、作品信息、新模式的 `scenario.json`、项目素材及恢复所需的会话信息，不是旧 Python 编辑器的 `snapshot.json`。

## 恢复位置

- macOS：`~/Library/Application Support/lom_modkit/rust/recovery/<进程号>-<时间>/`
- Windows：`%APPDATA%/lom_modkit/rust/recovery/<进程号>-<时间>/`
- Linux：`~/.local/share/lom_modkit/rust/recovery/<进程号>-<时间>/`

每个会话目录使用标准项目结构：`manifest.json`、`story/`、`assets/`，以及 `session.json`。编辑器只更新自己已成功写入的文件；撤销新增章节或删除素材后，也会清理该恢复副本中对应的旧文件，不扫描删除未知文件。

Windows 的项目与恢复副本写入已修复较深路径下的原子替换失败：临时文件和目标文件使用已创建父目录的规范化路径。写入错误仍会显示，不能因恢复目录里有部分文件就认定副本完整；能被列为候选也不等于恢复成功，仍需实际载入并核对项目。

## 能恢复哪些修改

已写入项目状态的表单、章节和有效离线测试编辑会进入下一次恢复副本。有效的素材名称或素材文件草稿即使尚未离开输入框，也会尝试加入副本；这不会改写正在输入的文本或移动光标。

格式尚未完成的输入不保证能恢复。例如无效测试 JSON、引用了缺失文件的素材草稿只保留在当前编辑会话中。素材草稿无法加入时，状态栏会说明副本尚未包含这些输入，其他已完成修改仍会保存。恢复副本也不保证包含最近 30 秒内的修改，因此仍应主动按 `⌘S` / `Ctrl+S` 保存。

## 异常退出后

启动时，编辑器查找带有 `session.json`、且可确认所属进程已结束的会话。Windows 使用原生进程状态检查，并比较进程创建时间与会话目录时间，避免复用的 PID 遮蔽旧副本。仍在运行、无法查询或会话目录格式无法识别的会话不会作为可恢复候选。

出现「发现未正常关闭的创作副本」时：

1. 点「恢复」载入副本。当前项目若有修改，会先让你选择保存、放弃或取消。
2. 检查章节、素材和选中步骤。恢复后的项目标为未保存，载入动作本身不覆盖原文件。
3. 原保存位置可识别时，可以保存回原项目；也可「另存项目目录…」保留单独副本。

恢复弹窗的右上关闭、Esc 和「稍后处理」都只隐藏本次提示，不删除副本。未保存修改弹窗关闭相当于取消切换，保留当前编辑；「移除副本」删除所选恢复目录。正常保存或确认退出会清理当前会话的恢复目录。
