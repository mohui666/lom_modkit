# 自动恢复

原生 Rust 编辑器在项目有未保存修改时，约每 30 秒更新一次本地恢复副本，不覆盖原项目。副本包含章节 JSON、作品信息、项目素材及恢复所需的会话信息，不是旧 Python 编辑器的 `snapshot.json`。

## 恢复位置

- macOS：`~/Library/Application Support/lom_modkit/rust/recovery/<进程号>-<时间>/`
- Windows：`%APPDATA%/lom_modkit/rust/recovery/<进程号>-<时间>/`
- Linux：`~/.local/share/lom_modkit/rust/recovery/<进程号>-<时间>/`

每个会话目录使用标准项目结构：`manifest.json`、`story/`、`assets/`，以及 `session.json`。编辑器只更新自己已成功写入的文件；撤销新增章节或删除素材后，也会清理该恢复副本中对应的旧文件，不扫描删除未知文件。

## 能恢复哪些修改

已写入项目状态的表单、章节和有效离线测试编辑会进入下一次恢复副本。有效的素材名称或素材文件草稿即使尚未离开输入框，也会尝试加入副本；这不会改写正在输入的文本或移动光标。

格式尚未完成的输入不保证能恢复。例如无效测试 JSON、引用了缺失文件的素材草稿只保留在当前编辑会话中。素材草稿无法加入时，状态栏会说明副本尚未包含这些输入，其他已完成修改仍会保存。恢复副本也不保证包含最近 30 秒内的修改，因此仍应主动按 `⌘S` / `Ctrl+S` 保存。

## 异常退出后

启动时，编辑器查找带有 `session.json`、且可确认所属进程已结束的会话。仍在运行或无法确认归属的会话不会作为可恢复候选；当前非 Unix 实现会保守跳过，不能据此承诺 Windows 的自动候选发现。

出现「发现未正常关闭的创作副本」时：

1. 点「恢复」载入副本。当前项目若有修改，会先让你选择保存、放弃或取消。
2. 检查章节、素材和选中步骤。恢复后的项目标为未保存，载入动作本身不覆盖原文件。
3. 原保存位置可识别时，可以保存回原项目；也可「另存项目目录…」保留单独副本。

「稍后处理」只关闭本次提示；「移除副本」删除所选恢复目录。正常保存或确认退出会清理当前会话的恢复目录。

本文描述当前实现，不代表已进行 Windows 或游戏实机验证。
