# 编辑器自动恢复

## 自动恢复副本

编辑器有未保存修改时，每 30 秒把整个多章节项目状态写入：

```text
%APPDATA%\lom_modkit\recovery\<独立会话 ID>\snapshot.json
```

恢复副本包含全部 Story、当前章节、Manifest、正式文件路径和来源类型。它不包含或执行 Lua，也不会把内容写回当前 `story.json`、`.lommod` 或 Mod 安装目录。

写入流程先在同一恢复目录创建临时文件，完成 flush/fsync 后再用 `os.replace` 原子替换 `snapshot.json`。快照 JSON 上限为 64 MiB；失败只写入崩溃日志，不会退而覆盖正式项目。

每次编辑器进程使用随机独立会话目录。正式保存后如果项目已经没有脏修改，快照会清除；正常关闭或明确放弃修改时，会清除快照并把会话标成 `closed`。进程异常终止时，最近一次完整原子快照和 `active` 会话标记会保留下来。

## 异常退出后的启动流程

启动时会扫描旧的 `active + snapshot` 会话，并跳过 PID 仍存活的其他编辑器实例。发现有效副本后，恢复窗口会列出保存时间、项目名、原来源路径和章节数，用户可以：

- **检查内容**：在只读 JSON 预览中查看全部恢复字段；超大文本只截断预览，不修改快照；
- **恢复所选**：先把内容载入内存并标为未保存，再为当前进程写一份新的原子快照；新快照成功后才消费旧候选；
- **丢弃所选**：删除该 snapshot，并把旧会话标为 `discarded`；
- **稍后处理**：不改变旧候选，下次启动仍会提示。

恢复时不会信任快照里的写入目标：所有恢复 Story 的正式路径都会清空。因此恢复动作本身绝不会覆盖原 `story.json` 或 `.lommod`；用户必须明确执行“另存为”或“导出 Mod”。损坏、超限、版本不支持、会话 ID 不一致或结构无效的候选不会载入。
